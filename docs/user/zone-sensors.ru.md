Для каждой управляемой сущности `climate.*` Velair создаёт два датчика, описывающих работу зоны:

- **Управление зоной** показывает, кто сейчас управляет зоной и какая конфигурация Velair применяется.
- **Диагностика доставки команд** показывает результат последней попытки Velair передать целевые настройки климатическому устройству через Home Assistant.

Это разные стороны работы системы. Зона может оставаться под автоматическим управлением, даже если последняя доставка команд была невозможна или завершилась ошибкой. Поэтому один датчик не заменяет другой.

Отдельный датчик **Состояние окружающей среды** предоставляет включённые `derived_metrics` и упорядоченный список `insights`, который существует только во время работы интеграции, когда включён мониторинг комфорта. Каждый элемент содержит `code`, `kind`, `tone` и поясняющие `metrics`. Эти наблюдения не выполняют действий с климатическими устройствами. Подробнее: [Комфорт в помещении](comfort.ru.md#comfort-insights).

Если включено сравнение с условиями на улице, этот же датчик предоставляет раздел `outdoor`. Он содержит исходные показания, отдельные значения абсолютной влажности внутри и снаружи, независимую оценку качества данных и описание пользы или возможных недостатков проветривания. Velair не создаёт промежуточных сущностей для отдельных показаний. Однако для сводного результата оценки, которым управляет бэкенд, создаётся отдельный датчик с перечисляемыми состояниями **Возможность проветривания**, описанный ниже.

<a id="environmental-condition"></a>
## Состояние окружающей среды

Датчик **Состояние окружающей среды** предоставляет текущее состояние для автоматизаций мониторинга комфорта. Он включён по умолчанию для каждого управляемого климатического устройства и обновляется по той же оценке бэкенда, что и панель Velair. Чтение его состояния не опрашивает исходный датчик и не выполняет климатических действий.

Его состояние сохраняет совместимость с существующей классификацией по физическим значениям температуры и влажности:

| Состояние | Значение |
| --- | --- |
| `monitoring_off` | Мониторинг комфорта для этого климатического устройства отключён. |
| `no_readings` | Сейчас нет пригодных показаний отслеживаемых параметров. |
| `temperature_comfortable` | Можно оценить только температуру, и она находится в настроенном диапазоне. |
| `humidity_comfortable` | Можно оценить только влажность, и она находится в настроенном диапазоне. |
| `comfortable` | Температура и влажность находятся в своих настроенных диапазонах. |
| `cold` / `hot` | Температура ниже или выше настроенного диапазона. |
| `dry` / `humid` | Влажность ниже или выше настроенного диапазона. |
| `cold_and_dry` / `cold_and_humid` | Оба показания пригодны для оценки, а температура ниже диапазона. |
| `hot_and_dry` / `hot_and_humid` | Оба показания пригодны для оценки, а температура выше диапазона. |

Эти значения совместимы с существующими автоматизациями. Они описывают настроенные физические диапазоны, а не медицинскую оценку или универсальные условия личного комфорта.

<a id="environmental-condition-attributes"></a>
### Атрибуты состояния окружающей среды

| Атрибут | Значение |
| --- | --- |
| `data_quality` | `complete`, `unverified`, `partial`, `stale` или `unavailable` для отслеживаемых показаний внутри помещения. `unverified` означает, что показания пригодны для использования, но хотя бы у одного отсутствует проверяемая временная метка публикации показания. |
| `data_issues` | Стабильные коды, поясняющие отсутствие, устаревание или некорректность данных внутри помещения. Атрибут отсутствует, если список пуст. |
| `range_summary` | Сводка по настроенным диапазонам, включая необязательное сопоставление с Humidex. |
| `ventilation_opportunity` | Текущее состояние оценки проветривания от бэкенда: область оценки, ожидаемые изменения, препятствия и причина. |
| `comfort_zone` | Выбранная простая модель, модель с подбором психрометрического диапазона или пользовательская модель области комфортных условий с учётом температуры и действующий при текущей температуре диапазон влажности. |
| `temperature_source` | Идентификатор сущности, из которой сейчас берётся температура внутри помещения, если она доступна. |
| `humidity_source` | Идентификатор сущности, из которой сейчас берётся влажность внутри помещения, если она доступна. |
| `derived_metrics` | Данные включённых показателей Humidex, точки росы и абсолютной влажности. Неотслеживаемые показатели отсутствуют. |
| `outdoor` | Необязательное сравнение условий внутри и снаружи: действующие пороги рекомендаций, качество данных, показания и описание пользы или компромиссов. |
| `insights` | Упорядоченные наблюдения с `code`, `kind`, `tone` и поясняющими `metrics`. Атрибут отсутствует, если список пуст. |

`derived_metrics` и `outdoor` отсутствуют, если соответствующая функция отключена. Если она включена, но показания отсутствуют, устарели или некорректны, раздел сохраняется с `availability` и пояснениями проблем, чтобы автоматизации не использовали старое значение. `insights` отсутствует, когда текущий список пуст. Исходные показания температуры и влажности внутри помещения остаются в исходных сущностях. Классификацию CO2 предоставляет отдельный датчик **Качество воздуха**.

Для модели с подбором психрометрического диапазона или пользовательской модели с учётом температуры значение `comfort_zone.effective_humidity_range` равно `null`, когда текущая температура непригодна для оценки. При этом показание влажности может оставаться видимым, но его состояние не определено: нельзя считать его находящимся внутри или снаружи предположительного диапазона.

`range_summary` содержит:

```yaml
status: within_range | outside_range | mixed | unavailable
thermal_relation: aligned | mixed | not_evaluated | unavailable
positions:
  temperature: below | within | above | null
  humidity: below | within | above | null
  humidex: below | within | above | null
```

Например, этот шаблон обнаруживает противоречивые тепловые показатели без разбора переведённой подписи:

```yaml
{% set summary =
   state_attr('sensor.velair_environmental_condition_living_room',
              'range_summary') %}
{{ summary is mapping and summary.get('thermal_relation') == 'mixed' }}
```

Это условие проверяет, что включённый показатель Humidex актуален и превышает настроенный диапазон температуры:

```yaml
{% set metrics =
   state_attr('sensor.velair_environmental_condition_living_room',
              'derived_metrics') or {} %}
{% set humidex = metrics.get('humidex', {}) %}
{{ humidex.get('availability') == 'current'
   and humidex.get('temperature_range_position') == 'above' }}
```

Это условие использует код наблюдения, определяемый бэкендом. Оно продолжает работать при смене языка интерфейса:

```yaml
{% set insights =
   state_attr('sensor.velair_environmental_condition_living_room',
              'insights') or [] %}
{{ insights
   | selectattr('code', 'eq', 'ventilation_may_help_cool')
   | list | count > 0 }}
```

При необязательном сравнении с условиями на улице проверяйте доступность данных перед использованием числового значения:

```yaml
{% set outdoor =
   state_attr('sensor.velair_environmental_condition_living_room',
              'outdoor') or {} %}
{% set comparison = outdoor.get('comparison', {}) %}
{% set thresholds = outdoor.get('guidance_thresholds', {}) %}
{% set temperature = comparison.get('temperature', {}) %}
{{ temperature.get('availability') == 'current'
   and temperature.get('potential') == 'cooling'
   and thresholds.get('temperature_delta') is number }}
```

<a id="entity-or-event"></a>
### Сущность или событие?

Используйте эту сущность, когда автоматизации нужно текущее состояние, в том числе после перезапуска Home Assistant. Обычный триггер состояния может реагировать на состояние температуры и влажности, сохраняя совместимость с существующими автоматизациями:

```yaml
triggers:
  - trigger: state
    entity_id: sensor.velair_environmental_condition_living_room
    to: hot_and_humid
```

Используйте `comfort_assessment_changed`, когда автоматизации нужно знать, что изменилось. Поля `previous_range_summary`, `range_summary_changed` и `range_status_changed` позволяют отличить переход между диапазонами от другого обновления мониторинга комфорта. Полный состав данных и готовая автоматизация приведены в разделе [Изменение оценки комфорта](automation-events.ru.md#comfort-assessment-changed).

<a id="ventilation-opportunity"></a>
## Возможность проветривания

Датчик **Возможность проветривания** для каждой зоны обновляется по событиям и предоставляет только наблюдения:

| Состояние | Значение |
| --- | --- |
| `unavailable` | Сейчас невозможно оценить комфорт, сравнение с улицей или необходимое настроенное показание. |
| `no_opportunity` | Параметры наружного воздуха не пересекают настроенные пороги в полезном направлении. |
| `may_help` | Наружный воздух приближает условия в комнате к комфортным, но Velair не может установить, что все параметры окажутся в настроенной области комфорта. |
| `comfort_possible` | Наружная температура находится в диапазоне, а при отслеживании влажности наружная влажность находится в полосе комфорта, рассчитанной при этой наружной температуре. |
| `trade_off` | Полезное изменение одного отслеживаемого параметра сопровождается известным ухудшением другого. |
| `already_comfortable` | Физическое состояние окружающей среды уже соответствует комфортным условиям. |

`comfort_possible` — осторожная оценка возможных условий, а не обещание результата при открытии окна. Velair не знает интенсивность воздухообмена, ветер, дождь, загрязнение наружного воздуха, солнечный нагрев, тепловую инерцию помещения или продолжительность открывания окна. Он никогда не открывает окно и не меняет управление климатом.

Атрибуты включают `evaluation_scope`, `potential_effects`, `blocked_by`, `reason`, наружные `data_quality` и `data_issues`, а также настроенные идентификаторы наружных источников. Если влажность внутри помещения отслеживается, но наружная влажность не настроена, температура может дать результат `may_help`, но не `comfort_possible`. Если мониторинг влажности намеренно отключён, результат `comfort_possible` только по температуре допустим.

`reason` — стабильный машинный код. Возможные значения:
`monitoring_off`, `outdoor_comparison_disabled`,
`indoor_temperature_unavailable`, `indoor_humidity_unavailable`,
`outdoor_temperature_unavailable`, `outdoor_humidity_unavailable`,
`already_comfortable`, `known_trade_off`, `no_useful_difference`,
`outdoor_conditions_within_comfort`, `outdoor_humidity_not_configured` и
`moves_toward_comfort`.

Для климатической сущности вроде `climate.living_room` новая запись в реестре обычно получает идентификатор вида:

```text
sensor.velair_ventilation_opportunity_living_room
sensor.velair_control_living_room
sensor.velair_delivery_diagnostics_living_room
```

Это предлагаемые идентификаторы, а не постоянный API. Home Assistant может добавить суффикс, чтобы избежать совпадения, а пользователь может переименовать сущность. Выбирайте фактические идентификаторы из своего реестра Home Assistant. Отображаемое имя сущности использует понятное имя управляемого климатического устройства, а предлагаемый идентификатор — объектную часть идентификатора климатической сущности. Имя служебного устройства Velair и его область не входят в предлагаемый идентификатор.

<a id="zone-control"></a>
## Управление зоной

Датчик **Управление зоной** включён по умолчанию; его состояние восстанавливается из планировщика после каждого перезапуска. Состояние указывает, кто сейчас управляет зоной:

| Состояние | Значение |
| --- | --- |
| `automatic` | Локальное управление выполняет Velair. Это включает расписание, ожидание, паузу, остановку, форсированный режим и адаптивную предварительную подготовку. Для их различения используйте `runtime_state`. |
| `manual` | Velair передал управление этим климатическим устройством ручной настройке — явно либо после обнаруженного внешнего изменения. Это отличается от режима Velair **Ручной**, который описывает выбор профиля. |
| `external` | Физическое выполнение для этой зоны осуществляет поддерживаемый внешний поставщик расписания. Изменение через карточку климатического устройства, пульт или другую автоматизацию не приводит к этому состоянию: когда Velair уступает управление такому изменению, состояние становится `manual`. |

Датчик остаётся доступным, когда требуется миграция единиц температуры, поскольку информация об управлении не является значением температуры.

<a id="zone-control-attributes"></a>
### Атрибуты управления зоной

| Атрибут | Значения или описание |
| --- | --- |
| `runtime_state` | `idle`, `scheduled`, `preconditioning`, `boost`, `paused`, `stopped`, `externally_managed`, `temperature_migration_required` или резервное значение `unknown`. |
| `schedule_source` | `default` для расписания зоны по умолчанию, `profile` для действующего расписания профиля или `profile_pause`, если действующий профиль приостанавливает зону. |
| `profile_id` / `profile_name` | Стабильный идентификатор и отображаемое имя профиля, управляющего зоной, если такой профиль применяется. |
| `mode_id` / `mode_name` | Стабильный идентификатор и отображаемое имя выбранного режима, если применяется пользовательский режим. |
| `manual_source` | Только для `manual`: `explicit`, если ручная настройка выбрана напрямую; `external_change`, если Velair уступил управление после обнаруженного изменения настроек климатического устройства; либо резервное значение `other`. |
| `manual_started_at` | Время начала текущей ручной настройки. |
| `manual_until` | Планируемое время окончания, если оно предусмотрено выбранной политикой ручного управления. Для бессрочной настройки атрибут может отсутствовать. |
| `manual_policy` | Только для `manual`: `until_next_block`, `for_duration`, `until_resumed` или резервное значение `unknown`. |

Необязательные атрибуты отсутствуют, когда неприменимы. Например, у сущности в состоянии `automatic` нет `manual_source` или `manual_until`.

Состояние управления и состояние работы разделены намеренно. Например:

- `automatic` с `runtime_state: paused` означает, что Velair по-прежнему управляет зоной, но пауза сейчас препятствует обычному выполнению расписания;
- `automatic` с `runtime_state: boost` означает, что временным форсированным режимом управляет Velair;
- `external` с `runtime_state: externally_managed` означает, что физическое выполнение осуществляет настроенный внешний поставщик, а не локальная отправка команд Velair климатическому устройству.

<a id="zone-delivery-diagnostics"></a>
## Диагностика доставки команд для зоны

**Диагностика доставки** — диагностическая сущность, отключённая по умолчанию. Включайте её, только если панели или автоматизации нужны сведения о последней локальной отправке команд:

1. Откройте **Настройки > Устройства и службы > Сущности** в Home Assistant.
2. Найдите сущность по имени управляемого климатического устройства и словам **Диагностика доставки**.
3. Откройте настройки сущности и включите её.

Датчик обновляется по событиям без опроса. Его состояние описывает последний наблюдавшийся результат отправки команд с момента запуска интеграции:

| Состояние | Когда возникает |
| --- | --- |
| `idle` | С момента запуска или очистки текущих сведений о доставке результат ещё не зарегистрирован. |
| `success` | Home Assistant принял всю последовательность климатических вызовов Velair. `retry_count` показывает, произошло ли это при первой попытке или повторе. |
| `failed` | Home Assistant отклонил климатический вызов службы. Для задач планировщика обычно начинается восстановление с ограниченным числом повторов; разовое действие без механизма восстановления может остаться в состоянии ошибки без повторных попыток. |
| `retrying` | После восстанавливаемой ошибки Velair начал одну из ограниченных повторных попыток. Это состояние может быть кратковременным. |
| `exhausted` | Первая попытка планировщика и обе отложенные повторные попытки завершились ошибкой. |
| `invalid_intent` | При восстановлении или повторной отправке Velair больше не смог преобразовать текущее намерение управления в допустимую команду. Обычные ошибки проверки служб и конфигурации отклоняются до достижения этого состояния. |
| `cancelled` | Активная или отложенная отправка заменена более новым намерением, явно отменена либо остановлена, пока ещё ожидала выполнения. Состояние может быть кратковременным, если сразу начинается новая задача. |
| `unavailable` | Управляемая климатическая сущность отсутствовала либо имела состояние `unknown` или `unavailable`, поэтому Velair не выполнил климатический вызов службы. Допустимое намерение планировщика определяется заново, когда сущность становится доступной. |

Сама диагностическая сущность остаётся доступной, чтобы состояние `unavailable` можно было наблюдать. Она также остаётся доступной, когда требуется миграция единиц температуры: сохранённые сведения о температуре используют единицу, записанную вместе с принятой целевой настройкой.

Сейчас Velair выполняет не более двух отложенных повторных попыток, примерно через 2 и 10 секунд. Это поведение восстановления, а не рекомендуемый контракт для автоматизаций: реагируйте на состояния, не полагаясь на точные задержки.

<a id="delivery-diagnostic-attributes"></a>
### Атрибуты диагностики доставки

| Атрибут | Значение |
| --- | --- |
| `updated_at` | Время последнего обновления состояния доставки. В начальном состоянии `idle` отсутствует. |
| `retry_count` | Номер попытки, соответствующей текущему конечному состоянию или повтору: `0` для первой попытки, затем `1` или `2`. При отмене сбрасывается в `0`. |
| `last_error_at` | Время последнего зарегистрированного результата `failed`, `exhausted` или `invalid_intent`. |
| `last_error_code` | `failed`, `exhausted`, `invalid_intent` или резервное значение `unknown_delivery_status`. Исходный текст исключения никогда не предоставляется. |
| `last_accepted_at` | Время, когда Home Assistant принял последнюю полную последовательность управляющих вызовов Velair. |
| `last_accepted_source` | `automatic`, `manual`, `boost` или `automatic_reassertion`. |
| `last_accepted_action` | `set_temperature`, `set_hvac_mode`, `turn_off` или резервное значение `other`. |
| `last_accepted_hvac_mode` | Режим HVAC, включённый в принятую целевую настройку, если он применялся. |
| `last_accepted_temperature_unit` | Единица температуры, записанная вместе с одиночной целевой температурой или диапазоном. |
| `last_accepted_temperature` | Принятая одиночная целевая температура, если применимо. |
| `last_accepted_target_temp_low` / `last_accepted_target_temp_high` | Принятые нижняя и верхняя границы для собственного диапазона устройства, если применимо. |

Вызовы через `velair.set_temperature` и `velair.set_hvac_mode` оба регистрируются с `last_accepted_source: manual`. Успешный вызов, меняющий только режим, имеет `last_accepted_action: set_hvac_mode` и режим HVAC; все атрибуты целевой температуры при этом отсутствуют или равны `null`.

Поля последней ошибки и последней принятой настройки хранят независимые сведения. Позднейший `success` меняет текущее состояние, но не стирает прежние значения `last_error_*`. Аналогично последующая ошибка не стирает последнюю принятую целевую настройку. Проверяйте время событий, когда автоматизации нужно сравнить их.

`success` означает, что Home Assistant принял вызовы служб. Оно не подтверждает доставку до устройства, работу оборудования или достижение целевой температуры в комнате. Физическое состояние проверяйте по климатической сущности и интеграции устройства. Room Assist может впоследствии изменить целевую температуру, отправляемую термостату; для применённой корректировки у него есть собственный датчик. Публикация внешних расписаний также имеет отдельное состояние в Velair и не отражается этим датчиком локальной доставки.

Все сведения о доставке существуют только во время работы интеграции. После перезапуска интеграции Velair или Home Assistant состояние возвращается в `idle`; успешный сброс данных Velair также очищает эти сведения. Они не восстанавливаются из Recorder или хранилища Velair.

<a id="automation-examples"></a>
## Примеры автоматизаций

Следующая автоматизация уведомляет только после исчерпания ограниченного числа повторных попыток Velair. Замените идентификатор из примера на фактический идентификатор из своего реестра сущностей:

```yaml
alias: Velair living room delivery exhausted
triggers:
  - trigger: state
    entity_id: sensor.velair_delivery_diagnostics_living_room
    to: exhausted
actions:
  - action: persistent_notification.create
    data:
      title: Velair delivery problem
      message: >-
        The living room target could not be delivered after
        {{ trigger.to_state.attributes.retry_count }} retries.
```

Это шаблонное условие проверяет, что автоматическое управление сейчас выполняет Velair и имеется активный блок расписания:

```yaml
condition: template
value_template: >-
  {{ is_state('sensor.velair_control_living_room', 'automatic')
     and state_attr('sensor.velair_control_living_room', 'runtime_state')
         == 'scheduled' }}
```

Используйте **Управление зоной** для текущего владельца управления и контекста планировщика, **Диагностику доставки** — для последнего результата вызовов служб, а `climate.living_room` — для состояния, сообщаемого устройством.
