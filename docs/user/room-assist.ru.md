Room Assist позволяет Velair использовать отдельный датчик температуры внутри комнаты для одного управляемого устройства, продолжая управлять реальной сущностью `climate.*`.

Это полезно для термостатических радиаторных клапанов, настенных термостатов или кондиционеров, чьи встроенные показания не отражают реальную температуру комнаты. Например, клапан рядом с радиатором может сообщать `22 °C`, когда комнатный датчик всё ещё показывает `20.5 °C`.

Все расчёты используют собственную единицу климатической сущности Home Assistant. Примеры ниже приведены в градусах Цельсия, но те же пределы гистерезиса, знаковая поправка, защита цели расписания, ширина диапазона, шаг температуры и обработка физических ограничений действуют напрямую в градусах Фаренгейта. Например, отклонение температуры комнаты от цели на `4 °F` означает поправку `4 °F`; она не считается абсолютной температурой и не получает сдвиг преобразования Цельсия в Фаренгейт.

Room Assist работает локально по событиям. Velair не выполняет непрерывный опрос и не отправляет данные датчиков за пределы Home Assistant.

<a id="what-it-does"></a>
## Назначение

Velair сохраняет цель расписания как реальную цель пользователя, но временно корректирует цель, отправляемую устройству, по отдельному комнатному датчику и показанию самого устройства. Комнатный датчик здесь не означает наружный датчик.

Для одной цели в фиксированном `heat` или `cool` ненулевая зона нечувствительности задаёт две границы переключения. Room Assist помнит, к какой границе движется, и меняет направление только после достижения противоположной границы комнатным датчиком. Это создаёт реальный цикл гистерезиса по отдельному датчику, вместо нового цикла встроенного датчика около центральной цели. Максимальная коррекция ограничивает знаковую поправку, рассчитанную от активной границы.

Одиночные цели `auto` и `heat_cool`, а также собственные диапазоны `heat_cool` сохраняют нейтральное поведение или запас вокруг диапазона. Velair не заставляет такие режимы попеременно включать отопление и охлаждение по циклу гистерезиса одной цели.

Исполнителем остаётся климатическая сущность. Velair не создаёт виртуальный термостат и не обходит прошивку устройства. Если термостат или клапан умеет напрямую привязывать отдельный датчик, такая встроенная возможность обычно остаётся лучшим первым выбором.

<a id="setup"></a>
## Настройка

1. Откройте вкладку Room Assist.
2. Разверните нужное устройство.
3. Выберите датчик температуры помещения.
4. Включите **Коррекцию по датчику помещения**.
5. Задайте **Зону нечувствительности Room Assist**: нижнюю и верхнюю границы переключения фиксированного отопления или охлаждения либо нейтральный запас автоматических режимов и диапазонов.
6. Измените **Максимальную коррекцию**, если значение по умолчанию слишком мало для комнаты или меньше разницы с целью, необходимой термостату для прекращения отопления или охлаждения.
7. Измените **Задержку обновления**, если обновления слишком медленные или частые.

Сам выбор комнатного датчика только сохраняет его. Velair начинает использовать показания как фактическую температуру помещения лишь после включения коррекции.

Коррекция не требует адаптивной подготовки. Она работает с обычными блоками расписания и блоками, которые подготовка начала раньше.

Температурный блок с **Сохранить режим** всё равно применяет запланированную цель. Room Assist использует фактический режим устройства; если оно выключено, Velair запускает совместимый поддерживаемый режим. Для температурного блока сохранение режима не означает сохранение текущей цели термостата. Блок только дополнительных параметров не содержит цели, поэтому Room Assist для него не работает.

Задержка обновления применяется после изменения комнатного датчика или температуры устройства. По умолчанию — `20` секунд. Задайте `0` для немедленного расчёта или до `300` секунд для объединения частых обновлений.

Зона нечувствительности независима от минимальной разницы адаптивной подготовки. По умолчанию — `0.3 °C` или `1 °F`; `0` отключает зону. Настройка допускает шаг `0.1` градуса до `5 °C` или `9 °F`. Сохранение при активном Room Assist сразу обновляет корректируемую цель.

Шкала текущей температуры показывает зону нечувствительности нейтральной полосой со штриховкой. Для фиксированной одиночной цели края — границы переключения гистерезиса, а состояние указывает активное направление. Для одиночных автоматических режимов полоса остаётся нейтральным запасом. Для диапазона `heat_cool` она простирается от нижней границы минус запас до верхней плюс запас. Шкала расширяется, чтобы оба края оставались видимыми. Полная переведённая подпись остаётся по центру реального диапазона, даже если уже своего текста: смысл не зависит от ширины графика. Полное объяснение также доступно вспомогательным технологиям и при наведении. При `0` полоса отсутствует, а неподвижная подпись явно сообщает отсутствие зоны. График и подпись обновляются по сохранённому серверному значению; скрытие `show_room_assist_deadband` в карточке Lovelace скрывает настройку, полосу и подпись вместе.

При обновлении с версии, где Room Assist использовал минимальную разницу адаптивной подготовки, Velair однократно копирует прежнее значение в собственную зону нечувствительности. Это сохраняет прежнюю ширину, включая историческое значение вне нового шага ввода 0,1 градуса; фиксированные `heat` и `cool` затем используют её в описанном ниже цикле. После преобразования настройки независимы: изменение одной никогда не меняет другую. Новая или сброшенная зона использует указанные выше значения для своих единиц.

<a id="understanding-the-live-status"></a>
## Текущее состояние

Вкладка Room Assist сообщает возможности Velair для каждого устройства, чтобы не приходилось выводить их только из цели термостата:

| Состояние | Значение |
| --- | --- |
| **Не настроено** | Отдельный комнатный датчик не выбран. |
| **Отключено** | Датчик сохранён, но Room Assist выключен. |
| **Простой** | Room Assist включён, но нет активного совместимого температурного блока или пригодного расчёта. |
| **Готов** | Есть показания и цель для расчёта, но корректируемая цель ещё не применялась. |
| **Корректирует** | Применена временная поправка цели или сдвиг диапазона. |
| **Удержание** | Room Assist удерживает автоматическую одиночную цель нейтральной, сохраняет диапазон или защита цели расписания удерживает безопасную сторону. Фиксированный цикл `heat` или `cool` может оставаться в состоянии **Корректирует** при движении через зону нечувствительности. |
| **Заблокировано** | Пауза, форсированный режим, ручное состояние или другое состояние планировщика сейчас имеют приоритет. |
| **Недоступно** | Устройство или требуемая возможность цели сейчас непригодны. Интерфейс показывает известную причину. |

При активном Room Assist обзор сокращает сведения до движения к нижней границе, к верхней, активности, удержания или защиты запланированной температуры и показывает запланированные и применённые значения. Ограничения минимальной и максимальной температуры термостата действуют отдельно от защиты расписания: вкладка Room Assist предупреждает о запрошенном, применённом и поддерживаемом значении, а Home Assistant получает одно постоянное уведомление до устранения физического ограничения.

<a id="fixed-heating-hysteresis-example"></a>
## Пример гистерезиса фиксированного отопления

Условия:

- Блок расписания: `21 °C`, `heat`.
- Зона нечувствительности: `±0.3 °C`.
- Нижняя граница: `20.7 °C`.
- Верхняя граница: `21.3 °C`.
- Максимальная коррекция: `2 °C`.
- Шаг устройства: `0.1 °C`.

Цикл по шагам:

1. Оба датчика сообщают `21.0 °C`. Поскольку новый фиксированный цикл отопления начинается внутри полосы, Velair безопасно выбирает движение **к нижней границе**.
2. Активная цель гистерезиса — `20.7 °C`. Поправка рассчитывается от этого края, а не центральной цели расписания `21 °C`:

   ```text
   correction = 20.7 - 21.0 = -0.3 °C
   climate target = 21.0 + (-0.3) = 20.7 °C
   ```

   Это намеренно не вызывающая отопление цель с учётом поддерживаемого шага и физических пределов.
3. При прохождении `20.9 °C` фаза сохраняется. Velair не запрашивает отопление только из-за пересечения центральной цели `21 °C`.
4. Когда комнатный датчик достигает `20.7 °C`, Velair переключается **к верхней границе** `21.3 °C`.
5. Предположим, комната показывает `20.7 °C`, а устройство — `20.5 °C`. Новая поправка запрашивает отопление:

   ```text
   correction = 21.3 - 20.7 = +0.6 °C
   climate target = 20.5 + 0.6 = 21.1 °C
   ```

6. Velair продолжает стремиться к верхней границе при прохождении `21.0 °C`. На `21.3 °C` переключается обратно к `20.7 °C`, применяет отрицательную поправку и повторяет цикл.

Видимая цель расписания остаётся `21 °C`. Временная цель — только значение, отправляемое термостату. Если поправка превышает максимальную коррекцию, Velair ограничивает её перед прибавлением к текущему показанию устройства.

Фаза фиксированного режима существует только во время работы. Новый блок, цель или режим HVAC, очистка Room Assist или перезагрузка Velair начинают новый цикл. Если новый `heat` начинается внутри полосы, он стремится к нижней границе, не запрашивая отопление сразу.

Когда защита меняет результат, текущее состояние объясняет оба значения: рассчитанную цель и фактически сохранённую Velair. Обзор показывает компактное состояние защиты расписания. Это нормальная защита, а не ошибка термостата, поэтому постоянного уведомления Home Assistant нет. Физические пределы продолжают использовать отдельные предупреждение и уведомление.

Устройство по-прежнему отвечает за защиту компрессора, минимальную длительность работы и физический отклик. Цикл гистерезиса даёт Velair более точную стратегию целевых значений, но не гарантирует момент изменения реле, клапана или компрессора.

<a id="heating-with-a-capped-delta"></a>
## Отопление с ограниченной поправкой

Условия:

- Блок расписания: `25 °C`, `heat`.
- Комнатный датчик: `18 °C`.
- Текущая температура устройства: `17.1 °C`.
- Зона нечувствительности: `0 °C` (прежняя знаковая поправка).
- Максимальная коррекция: `5 °C`.

Температура комнаты значительно отличается от цели:

```text
25 - 18 = 7 °C
```

Velair ограничивает поправку настроенным максимумом:

```text
assist delta = 5 °C
climate target = 17.1 + 5 = 22.1 °C
```

При шаге `0.5 °C` цель отопления округляется вниз до `22 °C`.

Это не позволяет отправлять термостату нереалистичные цели, сохраняя достаточное открытие для отопления комнаты.

<a id="fixed-cooling-hysteresis-example"></a>
## Пример гистерезиса фиксированного охлаждения

Условия:

- Блок расписания: `24 °C`, `cool`.
- Зона нечувствительности: `±0.5 °C`.
- Нижняя граница: `23.5 °C`.
- Верхняя граница: `24.5 °C`.
- Максимальная коррекция: `2 °C`.
- Шаг устройства: `0.5 °C`.

Охлаждение симметрично, но новый цикл внутри полосы безопасно начинается **к верхней границе**, не запрашивая охлаждение сразу:

1. При обоих датчиках на `24.0 °C` активный край — `24.5 °C`:

   ```text
   correction = 24.5 - 24.0 = +0.5 °C
   climate target = 24.0 + 0.5 = 24.5 °C
   ```

   Повышение цели фиксированного охлаждения препятствует охлаждению.
2. Фаза сохраняется, пока температура в комнате меняется в пределах этой полосы. Когда отдельный комнатный датчик достигает `24.5 °C`, Velair переключается к `23.5 °C`.
3. Если комната показывает `24.5 °C`, а устройство — `25.0 °C`:

   ```text
   correction = 23.5 - 24.5 = -1.0 °C
   climate target = 25.0 - 1.0 = 24.0 °C
   ```

   Это запрашивает охлаждение.
4. Velair продолжает стремиться к нижнему краю при прохождении `24.0 °C`. На `23.5 °C` переключается обратно к `24.5 °C` и повторяет цикл.

Выравнивание по шагу и физические пределы действуют для каждой временной цели. Реальный цикл охлаждения остаётся за прошивкой устройства.

<a id="how-legacy-inversion-and-scheduled-protection-work-together"></a>
## Совместная работа прежней инверсии и защиты расписания

Знаковая инверсия и защита цели расписания решают две части одной задачи. Инверсия меняет направление поправки после пересечения цели комнатной температурой. Защита расписания — последняя безопасная граница, если обратная поправка всё ещё оставляет цель фиксированного режима на стороне, требующей работы относительно расписания.

Примеры охлаждения ниже используют расписание `22 °C`, зону `0 °C`, шаг `0.5 °C` и максимум поправки, достаточный, чтобы не ограничивать расчёт. Столбцы «без инверсии» и «до защиты» объясняют промежуточные значения; это не выбираемые режимы Room Assist.

| Комнатный датчик | Показание устройства | Без инверсии после пересечения | Знаковый результат до защиты | Итоговая цель | Причина |
| --- | --- | --- | --- | --- | --- |
| `24 °C` | `25.1 °C` | Не применимо | `23.5 °C` | `23.5 °C` | Комнате всё ещё нужно охлаждение. |
| `21 °C` | `19 °C` | `19 °C` | `20 °C` | `22 °C` | Инверсия повышает цель, но она всё ещё запрашивала бы охлаждение, поэтому применяется нижний предел расписания. |
| `21 °C` | `25 °C` | `25 °C` | `26 °C` | `26 °C` | Более сильная обратная цель уже безопасно выше расписания и сохраняется. |

Отопление симметрично. При расписании отопления `20 °C`, комнатном показании `21 °C` и внутреннем `24 °C` знаковый результат — `23 °C`; защита вместо него применяет верхнюю границу расписания `20 °C`. Если комната показывает `24 °C`, а внутренний датчик `21.5 °C`, более сильный обратный результат `17.5 °C` уже безопасен и сохраняется.

Поэтому инверсия полезна и с защитой: она может сильнее сместить цель в сторону, не требующую работы, если показание устройства позволяет, а защита покрывает случаи ухода внутреннего показания на неверную сторону.

При ненулевой зоне фиксированные `heat` и `cool` используют описанный цикл с памятью фазы, а не меняют направление на центральной цели. `0` сохраняет прежний знаковый расчёт: поправка меняет знак при пересечении цели расписания, без сохранения фазы.

Совместимые одиночные `auto` и `heat_cool` тоже сохраняют прежний знаковый расчёт. Внутри зоны Velair использует ближайшую поддерживаемую цель к показанию устройства вместо принудительного чередования отопления и охлаждения. Собственный диапазон `heat_cool` сохраняет обе пользовательские границы и получает полный корректируемый диапазон, описанный ниже.

<a id="device-hysteresis-and-minimum-run-time"></a>
## Гистерезис устройства и минимальная длительность работы

Room Assist управляет целью, отправляемой через Home Assistant. Он не заменяет гистерезис прошивки, защиту компрессора, минимальную длительность работы или решение устройства о простое при равенстве цели.

Например, цикл отопления, движущийся к нижней границе, отправляет цель для прекращения запроса отопления до достижения этого края комнатным датчиком. Устройство с широким внутренним гистерезисом или минимальным временем работы может временно начать или продолжать нагрев. Velair не выводит недокументированный запас остановки конкретного устройства и не проверяет `hvac_action` для изменения фазы.

Защита расписания не позволяет цели уходить за пользовательское расписание вслед за внутренним датчиком; немедленную остановку HVAC она не обещает. Встроенная привязка отдельного датчика или калибровка остаётся лучшим вариантом при наличии. Используйте блок `Выкл.`, если нужна явная остановка, а не удержание под управлением термостата.

Максимальная коррекция должна допускать обратную поправку, нужную устройству. Редактор сохраняет объяснение под именем настройки, чтобы его не пропустить. Например:

```text
Thermostat stopping gap: 2.5 °C
Maximum assist delta:    2.0 °C  -> may be insufficient
Maximum assist delta:    3.0 °C  -> permits enough inverse correction
```

Задание `3 °C` не применяет такую поправку сразу. Оно только позволяет достичь её, когда разница комнатной температуры этого требует.

<a id="why-climate-target-can-differ-from-the-calculation"></a>
### Почему уставка устройства может отличаться от расчёта

**Уставка климата** — цель, сейчас сообщаемая сущностью, пока Room Assist готов или заблокирован. При корректировке или удержании применённой одиночной цели вместо неё показана временная уставка, отправленная Velair. Ни одно значение не является запланированной целью комнаты или активной границей гистерезиса. Устройство принимает цели на своей сетке, поэтому Velair может приводить итоговую уставку к действующему сообщённому, последнему известному, ручному или стандартному шагу.

Например, при фиксированном охлаждении расчёт может дать `23.9 °C` для устройства с шагом `0.5 °C`. Velair применяет `24.0 °C`: округление вверх не усиливает охлаждение относительно расчёта. Отопление округляется вниз, одиночные автоматические режимы — к ближайшему шагу. Информационная кнопка рядом с **Уставкой климата** объясняет показанное значение; если выравнивание действительно изменило применённую уставку, показывает расчёт, действующий шаг и результат. Физические минимум и максимум и защита расписания сообщаются отдельно и не называются выравниванием шага.

<a id="heatcool-range-example"></a>
## Пример диапазона нагрева и охлаждения

Room Assist поддерживает собственные диапазоны `heat_cool`. Нижняя и верхняя цели рассматриваются как одна комфортная полоса и всегда сдвигаются вместе, сохраняя расстояние между ними.

Условия:

- Диапазон расписания: `19–24 °C`.
- Комнатный датчик: `18 °C`.
- Текущая температура устройства: `22 °C`.
- Максимальная коррекция: `2 °C`.
- Шаг устройства: `0.5 °C`.

Комната на `1 °C` ниже границы отопления. Velair располагает нижнюю границу на `1 °C` выше показания устройства и сдвигает верхнюю на ту же величину:

```text
applied range = 23–28 °C
```

Устройство показывает `22 °C`, ниже применённой нижней границы, и может запросить отопление. Если комната позже превысит `24 °C`, Velair аналогично использует верхнюю границу для охлаждения. При первом входе комнаты в запланированную полосу с запасом нечувствительности вокруг границ Velair располагает применённую полосу так, чтобы показание устройства находилось внутри. Затем удерживает её стабильной, пока комнатный датчик остаётся внутри полосы. Последующие движения внутреннего датчика не отслеживаются целью, поскольку показание может само меняться при работе компрессора, вентилятора, клапана или радиатора.

Применённый диапазон всегда выровнен по шагу и сдвигается целиком при достижении физических пределов цели. Velair никогда не корректирует Min и Max независимо.

Если рассчитанная одна цель или диапазон выходит за поддерживаемый минимум или максимум, Velair применяет ближайший допустимый результат. Перед графиком показаны запрошенная и применённая цели и достигнутый предел. Home Assistant создаёт одно постоянное уведомление активного предела; повторные обновления не создают дубликатов, а восстановление удаляет уведомление.

<a id="when-velair-does-nothing"></a>
## Когда Velair ничего не делает

Room Assist требует корректного положительного действующего шага цели. Сначала используется `target_temp_step` управляемого устройства. При отсутствии последний корректный шаг этой сущности защищает прежнюю сетку целей. Затем используется ручной запасной шаг зоны из настроек, по умолчанию `1`, если других значений нет. Сохранение поля при отсутствующем атрибуте делает явное значение основным, очищая запомненное наблюдение; следующее корректное сообщение снова запоминается. Velair не предполагает связи с другой сущностью.

Room Assist не применяет корректировку, если:

- комнатный датчик не выбран;
- коррекция по датчику помещения отключена;
- планировщик не в автоматическом режиме;
- устройство на паузе или в форсированном режиме;
- нет активного температурного блока;
- активный блок — `Выкл.`;
- температура комнатного датчика или устройства недоступна или нечисловая;
- рассчитанное изменение меньше шага температуры устройства;
- режим HVAC нельзя интерпретировать как отопление или охлаждение.

В этих случаях Velair сохраняет или восстанавливает обычную цель расписания, когда это безопасно.

<a id="external-adjustments-and-manual-adjustment"></a>
## Внешние изменения и ручная настройка

При стандартном правиле **Сохранять автоматически** Room Assist сохраняет приоритет; после обнаруженного внешнего изменения цели или HVAC Velair пересчитывает и повторно применяет текущую корректировку. При любом ручном правиле Room Assist намеренно уступает, когда изменение переводит устройство в **Ручную настройку**. Velair получает полное внешнее состояние из события Home Assistant, очищает активную поправку без восстановления расписания и сохраняет внешнюю одиночную цель или диапазон `heat_cool`. Так Room Assist не борется сразу с изменением из карточки, пульта или другого внешнего источника.

Пример:

```text
Scheduled cooling target: 24 °C
Room Assist temporary target: 26 °C
External adjustment: 23 °C
Result during Manual adjustment: 23 °C
```

При возобновлении автоматического расписания Velair определяет действующее в тот момент расписание или намерение профиля. Room Assist может рассчитать новую поправку по текущим показаниям; старые `26 °C` или фаза фиксированного режима не восстанавливаются. Перезагрузка Velair или Home Assistant также сбрасывает несохраняемые рабочие данные: текущий блок определяется снова и выбирается безопасная новая фаза по текущему режиму и комнате.

Подходящее внешнее изменение либо сохраняет автоматический приоритет, либо начинает или обновляет ручную настройку по правилу устройства. Правила, службы, взаимодействия с форсированным режимом и профилями и ограничения определения источника описаны в [Внешних изменениях и ручной настройке](manual-control.ru.md).

<a id="planned-return"></a>
## Запланированное возвращение

При [Запланированном возвращении](planned-return.ru.md) Room Assist следует временной цели прибытия каждой зоны после начала её подготовки. Он не продолжает использовать температуру Away и не возвращается к ней при изменении блока Away. Остальные зоны следуют Away до своей подготовки.

Например, цель отсутствия 16 градусов заменяется целью прибытия 21 градус при начале подготовки комнаты. Room Assist может менять физическую уставку для достижения 21 градуса на комнатном датчике. Ручная настройка и явные паузы приостанавливают работу для зоны. Явный выбор режима или профиля отменяет раннюю подготовку эпизода и сохраняет выбор. Отмена возвращения тоже снимает подготовку; после подтверждённого ухода восстанавливает записанные прежние режим и профили. См. [примеры отмены](planned-return.ru.md#cancelling-a-return-examples).

<a id="adaptive-preconditioning"></a>
## Адаптивная предварительная подготовка

Когда включённая адаптивная подготовка раньше запускает будущий блок, Room Assist следует этой будущей цели до запланированного времени комфорта.

Это важно, поскольку текущее время ещё может относиться к старому блоку. Velair считает уже начатый блок подготовки активной управляемой целью, поэтому Room Assist не рассчитывает по прежнему блоку.

При включённой коррекции по датчику помещения адаптивная подготовка тоже использует выбранный комнатный датчик для решений и обучения.

<a id="automation-events"></a>
## События для автоматизаций

Velair публикует стандартное событие Home Assistant `velair_event`.

Room Assist публикует:

- `room_sensor_assist_state_changed`: коррекция включена или отключена;
- `room_sensor_assist_updated`: применена временная корректируемая цель;
- `room_sensor_assist_restored`: Velair прекратил временную коррекцию и восстановил обычную цель расписания, где возможно.

Полные данные и все причины восстановления — в [Событиях для автоматизаций](automation-events.ru.md#room-sensor-assist-state-changed).

Пример данных события:

```yaml
event: room_sensor_assist_updated
entity_id: climate.living_room
room_temperature_entity_id: sensor.living_room_temperature
target_temperature: 21
applied_temperature: 20
room_temperature: 18
climate_temperature: 17.1
assist_delta: 3.3
applied_offset: 2.9
direction: heat
hvac_mode: heat
hysteresis_phase: towards_upper
hysteresis_target: 21.3
deadband_low: 20.7
deadband_high: 21.3
reason: current_schedule
```

Четыре поля гистерезиса необязательны. Они появляются для фиксированного одиночного `heat` или `cool` с ненулевой зоной и отсутствуют для прежней поправки с нулевой зоной, одиночных автоматических режимов и собственных диапазонов.

Обновление диапазона использует полные запланированную и применённую полосы вместо полей одиночной цели:

```yaml
event: room_sensor_assist_updated
entity_id: climate.living_room
room_temperature_entity_id: sensor.living_room_temperature
target_temp_low: 19
target_temp_high: 24
applied_target_temp_low: 23
applied_target_temp_high: 28
room_temperature: 18
climate_temperature: 22
assist_delta: 1
range_shift: 4
direction: heat
hvac_mode: heat_cool
reason: current_schedule
```

Пример триггера автоматизации:

```yaml
trigger:
  - platform: event
    event_type: velair_event
    event_data:
      event: room_sensor_assist_updated
      entity_id: climate.living_room
```

Room Assist также управляется автоматизациями через:

- `velair.enable_room_sensor_assist`;
- `velair.disable_room_sensor_assist`.

<a id="lovelace"></a>
## Lovelace

Room Assist доступен как карточка Lovelace:

```yaml
type: custom:velair-card
view: sensors
entities:
  - climate.living_room
```

Шкала текущей температуры разделяет два сравнения. Для одной цели верхняя линия сравнивает комнатный датчик с целью расписания, нижняя — показание устройства с его целью. В фиксированных `heat` и `cool` штрихованная полоса отмечает обе границы гистерезиса, состояние называет активную. В одиночных автоматических режимах это нейтральный запас. Для диапазона красные и синие скобки показывают полные запланированную и применённую полосы с обеими границами. Один знаковый соединитель **Сдвиг диапазона** идёт между центрами, отражая сдвиг всей полосы, а не одной границы. Индикаторы описывают только отправленную Velair уставку; они не утверждают, что термостат, клапан или компрессор сейчас нагревает или охлаждает.

В узких столбцах панели шкала прокручивается горизонтально для читаемости температурных отметок.

Для компактного представления только в панели карточка Room Assist может скрывать отдельные части:

```yaml
type: custom:velair-card
view: sensors
entities:
  - climate.living_room
show_room_assist_switch: false
show_room_assist_sensor: false
show_room_assist_deadband: false
show_room_assist_max_delta: false
show_room_assist_debounce: false
show_room_assist_live_status: true
```

Пропущенные параметры `show_room_assist_*` по умолчанию равны `true`.
