<a id="panel-navigation-and-direct-links"></a>
## Навигация по панели и прямые ссылки

Панель в боковом меню обновляет URL при переходе между вкладками и подразделами расписаний и шаблонов. Обновление страницы или открытие скопированного URL восстанавливает раздел. Кнопки браузера Назад и Вперёд также учитывают эту навигацию.

| Раздел | Путь |
| --- | --- |
| Обзор | `/velair` |
| Расписания: По умолчанию | `/velair/schedules/default` |
| Расписания: Профили | `/velair/schedules/profiles` |
| Режимы | `/velair/modes` |
| Шаблоны: Шаблоны | `/velair/templates/templates` |
| Шаблоны: Климатические пресеты | `/velair/templates/presets` |
| Датчики | `/velair/sensors` |
| Комфорт | `/velair/comfort` |
| Предварительная подготовка | `/velair/preconditioning` |
| Запланированное возвращение | `/velair/planned-return` |
| Диагностика | `/velair/diagnostics` |
| Настройки | `/velair/settings` |

Используйте эти пути в действиях навигации панелей Home Assistant или добавляйте их к адресу своего Home Assistant, чтобы получить полную ссылку. Открытие ссылки выбирает раздел; оно не активирует режим и не меняет настройки климатических устройств.

Например, кнопка на панели может открывать библиотеку климатических пресетов:

```yaml
type: button
name: Velair climate presets
icon: mdi:thermometer-lines
tap_action:
  action: navigate
  navigation_path: /velair/templates/presets
```

Замените `navigation_path` на любой путь из таблицы. Для этого используется стандартное [действие навигации панели](https://www.home-assistant.io/dashboards/actions/) Home Assistant. Для закладки или ссылки из другого приложения используйте адрес своего Home Assistant с нужным путём, например `https://your-home-assistant.example/velair/schedules/profiles`.

`/velair/schedules` открывает расписания по умолчанию, а `/velair/templates` — шаблоны. `/velair/preconditioning` открывает адаптивную предварительную подготовку, `/velair/planned-return` — запланированное возвращение. Старые пути `/velair/preconditioning/preconditioning` и `/velair/preconditioning/planned-return` по-прежнему открывают соответствующие вкладки. `/velair/overview` открывает Обзор, а старый путь `/velair/profiles` — Режимы. Неизвестный подраздел открывает подраздел вкладки по умолчанию; неизвестная вкладка открывает Обзор. Пути нормализуются без добавления записи в историю.

Ссылки не сохраняют выбор отдельного климатического устройства, дня недели, профиля, шаблона или пресета. Несохранённые изменения не восстанавливаются после обновления страницы. Если навигация приведёт к их потере, действуют обычные запросы подтверждения; отмена сохраняет текущий раздел и URL. Дополнительные карточки Lovelace сохраняют URL своих панелей.

Пока боковая панель открыта, её вкладки используют общие последние данные, подтверждённые бэкендом. После первой загрузки переключение вкладок не повторяет начальную загрузку. Обновления продолжаются при навигации, и запросы подтверждения для несохранённых изменений остаются в силе. Обновление страницы заново загружает данные и не восстанавливает черновики. Дополнительные карточки Lovelace используют отдельную от панели сессию. Смонтированные карточки на одном подключении Home Assistant совместно используют начальную загрузку и текущие обновления, сохраняя собственные элементы управления и несохранённые изменения. Lovelace может оставлять карточки смонтированными при переходе к другому представлению панели, позволяя вернуться без повторной загрузки. Общая сессия закрывается при размонтировании последней карточки; обновление страницы запускает новую загрузку. Менять YAML не нужно.

<a id="help-and-documentation"></a>
## Помощь и документация

Откройте **Настройки → Помощь и сообщество**, чтобы просмотреть документацию, сообщить о проблеме в GitHub Issues или поделиться вопросами и предложениями в Discussions. Значок помощи рядом с заголовком раздела или справа от пункта подменю открывает краткое пояснение и ссылку **Открыть руководство**. Открытие помощи для пункта подменю не выбирает его и не меняет ваши правки. Пояснение и руководство относятся именно к этому пункту, даже если его раздел сейчас не открыт. В Настройках значок помощи для **Внешние настройки** также предлагает соответствующее руководство. Все значки помощи используют вопросительный знак и подсвечиваются при наведении; значки информации по-прежнему дают краткие пояснения к полям. Закройте окно помощи кнопкой закрытия, Escape или щелчком вне окна; фокус клавиатуры вернётся к значку помощи.

Краткие пояснения доступны внутри Velair на всех поддерживаемых языках интерфейса, в том числе без подключения к Интернету. Ссылки на руководства используют язык вашего Home Assistant при наличии перевода, а при его отсутствии открывают английский вариант отдельно для каждого руководства. Пометка **На английском языке** появляется только тогда, когда английский используется из-за отсутствия перевода на ваш язык. Переведённые руководства показывают состояние синхронизации с оригиналом и лингвистической проверки; при наличии ожидающих изменений они содержат ссылку на английский оригинал. Сборки опубликованных версий открывают документацию из соответствующего тега версии; сборки для разработки открывают текущую документацию `main`. Ссылки на документацию и сообщество открывают GitHub в новой вкладке и требуют Интернет только при открытии; они не загружают диагностику или локальную конфигурацию автоматически.

<a id="concepts"></a>
## Основные понятия

Velair управляет расписаниями сущностей `climate.*`, выбранных при настройке интеграции. Каждая выбранная сущность представляет управляемую климатическую зону.

Расписание состоит из блоков для дней недели. Блок начинается в указанное время и может:

- задавать целевую температуру, при необходимости вместе с режимом HVAC и поддерживаемыми параметрами, например режимом вентилятора, предустановкой, качанием жалюзи, горизонтальным качанием или целевой влажностью;
- задавать один или несколько поддерживаемых параметров без отправки целевой температуры или изменения режима HVAC;
- менять только режим HVAC, оставляя целевую температуру под управлением устройства;
- выключать климатическую сущность.

Блок действует до начала следующего блока недельного расписания. Это включает полночь и дни без блоков: до первого блока дня Velair сохраняет самый последний блок одного из предыдущих дней. Временная шкала показывает этот унаследованный период отдельно, чтобы было ясно, где блок был настроен изначально.

<a id="external-adjustments-and-manual-adjustment"></a>
## Внешние настройки и ручная настройка

Для каждой зоны можно выбрать, что Velair делает при изменении режима HVAC или уставки вне Velair, например через климатическую карточку Home Assistant, ИК-пульт или другую автоматизацию. Настройте **Внешние настройки** в строке каждого управляемого климатического устройства в **Настройках**:

- **Сохранять автоматически** — вариант по умолчанию, повторно применяющий текущее намерение управления Velair.
- **До следующего блока** сохраняет изменение до начала следующего действующего блока.
- **На заданное время** возобновляет управление после настроенного количества минут.
- **До возобновления** ожидает явного действия.

Когда Velair уступает управление, Обзор выбирает **Ручная настройка** в постоянном переключателе автоматического/ручного управления. Это не режим Velair **Ручной**: режим Ручной описывает способ выбора профилей, а ручная настройка — кто сейчас управляет одним климатическим устройством. Возобновление повторно применяет расписание активного профиля, расписание по умолчанию или другое текущее намерение планировщика. Другие независимые причины паузы остаются в силе.

Обзор выбирает **Автоматическое расписание**, пока климатическим устройством управляет Velair. Выберите **Ручная настройка**, чтобы сохранить текущее состояние без предварительного изменения устройства; используется уже сохранённая в Настройках политика ручного управления. Если сохранено **Сохранять автоматически**, явное ручное действие остаётся ручным до возобновления, не меняя эту настройку. Та же операция доступна как `velair.enter_manual_adjustment`; она фиксирует текущее состояние обогрева, охлаждения, выключения или нативного диапазона и принимает только ID климатической сущности.

При **Сохранять автоматически** Room Assist пересчитывает и повторно применяет целевое значение, за которое отвечает. При ручной политике он уступает управление без восстановления своей запланированной коррекции. Поддерживаются как одна температура, так и нативные диапазоны.

Полное руководство объясняет границы обнаружения, все политики, повторные изменения, профили и режимы, приоритет форсированного режима и пауз, поведение при перезапуске, точный YAML служб/событий и пошаговые примеры во времени. См. [Внешние изменения и ручная настройка](manual-control.ru.md).

Velair рассчитывает предстоящие события в бэкенде и назначает точные однократные обратные вызовы через Home Assistant. Интерфейс подписывается на обновления бэкенда по WebSocket, поэтому постоянный опрос не нужен.

Во время запланированного возвращения Обзор показывает компактную сводку по дому: недельное или разовое происхождение, текущий процесс и соответствующее время подтверждения или прибытия. Её кнопка навигации открывает вкладку запланированного возвращения; сводка не дублирует элементы управления уходом из дома. Проблема может оставаться видимой, даже когда уход сейчас не выполняется.

Каждое затронутое климатическое устройство показывает фиолетовый индикатор запланированного возвращения, когда бэкенд сообщает, что им сейчас управляет конфигурация отсутствия или подготовка к прибытию. Обычное рабочее состояние, профиль и сведения Room Assist остаются видимыми. Будущее время подготовки — прогнозная информация, а не признак активного управления. Ручное управление, форсированный режим, независимые паузы, остановленное расписание и внешнее выполнение сохраняют приоритет. Устройство, которое просто продолжает расписание по умолчанию в пользовательском режиме отсутствия, не получает индикатор отсутствия. Индикатор описывает намерение управления; он не доказывает успешную доставку команды или достижение комнатой целевой температуры.

Если управляемое климатическое устройство не публикует `target_temp_step`, его строка в **Настройках** показывает **Шаг** температуры. Velair использует `1` по умолчанию и позволяет указать фактический положительный шаг устройства. Velair запоминает последний допустимый шаг, сообщённый Home Assistant, поэтому прекращение публикации атрибута не делает существующие дробные цели недопустимыми. Публикуемый сейчас шаг всегда имеет приоритет. Сохранение ручного значения при отсутствии атрибута заменяет запомненное резервное значение. Если сущность вновь публикует шаг, Velair запоминает новую сетку значений, хотя ручное резервное значение остаётся сохранённым.

Раздел **Диагностика** панели предоставляет доступный только для чтения снимок планировщика и отдельных зон, ограниченный журнал текущего запуска и JSON-отчёт с удалёнными чувствительными данными для приложения к сообщениям о проблемах. Он не добавляет опрос и не зависит от Recorder. На компьютере ширину столбцов журнала можно менять в текущей сессии; при перезагрузке панели ширина сбрасывается и никогда не сохраняется постоянно. На мобильных устройствах те же события показываются в компактном адаптивном виде без изменения ширины столбцов.

Диагностика также показывает состояние запланированного возвращения для дома, фактическое участие выбранного климатического устройства, оценку подготовки и причины её приостановки. Отключённая недельная процедура не означает недоступность разовых возвращений. Категория журнала **Запланированное возвращение** записывает принятое планирование, подтверждение, уход, изменения времени прибытия, начало подготовки, завершение, отмену и ошибки. Она использует общий существующий предел в 100 событий и очищается при перезапуске; предпочтения категорий сохраняются. Обновление любого представления не добавляет записи. Отчёты включают этот контекст, удаляя идентификаторы режимов и профилей даже при явном включении ID сущностей.

Сводка возвращения в Обзоре использует обычный фон темы, тонкую фиолетовую рамку и главный значок; остальные значки сохраняют цвет текста. Принятое будущее возвращение добавляет счётчики подготовки с помощью по наведению, фокусу и касанию. Подтверждённый уход имеет шкалу рядом со сводкой или под ней при меньшей ширине. Переход открывает подробности без повторения управления уходом. Подготовка отделена от индикатора текущего управления: термостат может ещё следовать отсутствию и показывать ожидание, подготовку, готовность, приостановку, недоступность или действие при прибытии, расчётное начало, цель и причину. Нет оценки — нет выдуманного времени; неактивное возвращение не сохраняет предпросмотр будущей подготовки.

<a id="home-assistant-entities"></a>
## Сущности Home Assistant

Velair создаёт постоянные сущности Home Assistant, дополняющие его кратковременные события автоматизации:

- **Следующее запланированное событие** — датчик даты и времени ближайшего ожидающего действия Velair. Его атрибуты включают все события в то же время, рассчитанное время применения и исходное целевое время, если адаптивная подготовка начинает блок раньше.
- **Состояние планировщика** показывает, ожидает ли Velair, выполняет ли расписание, действует ли временное переопределение или пауза. Атрибуты включают глобальный режим и срок паузы. Сведения о предстоящих событиях и переопределениях зон остаются в отдельных датчиках, чтобы не дублировать историю Recorder.
- **Состояние диагностики** — диагностический датчик с перечисляемыми состояниями `ok`, `warning` и `error`. Он предоставляет только компактные атрибуты: состояние планировщика, число исправных устройств, устройств с предупреждениями и устройств с ошибками, количество проблем и активные коды проблем. Так текущая работоспособность доступна панелям и автоматизациям по состоянию без исходного текста исключений.
- **Текущая целевая температура** создаётся для каждого управляемого устройства. Она показывает цель, которой сейчас управляет Velair, включая форсированные режимы и блоки, уже начатые адаптивной подготовкой. Единица соответствует климатической сущности. Для нативного диапазона скалярное состояние недоступно: единственного правильного значения нет; используйте атрибуты `target_temp_low` и `target_temp_high`.
- **Состояние окружающей среды** создаётся для каждого управляемого устройства. Оно показывает понятные состояния: комфортно, холодно, влажно или жарко и влажно. Качество данных и ID исходных сущностей сохраняются как компактные атрибуты без копирования исходных показаний температуры и влажности.
- **Возможность проветривания** создаётся для каждого управляемого устройства. Она предоставляет осторожную наблюдательную оценку с перечисляемыми состояниями: может ли наружный воздух приблизить комнату к настроенной области комфорта. Она не открывает окна и не управляет климатом.
- **Качество воздуха** создаётся для каждого управляемого устройства и хранит независимую оценку CO2: хорошее, повышенный уровень, плохое, недоступно или не отслеживается.
- **Переопределение** зоны показывает отсутствие переопределения, активный форсированный режим или активную паузу зоны.
- **Управление** создаётся для каждого управляемого устройства и показывает локальное состояние `automatic`, активную ручную настройку или управление физическим выполнением со стороны внешнего поставщика расписания. Атрибуты предоставляют текущий контекст планировщика, профиля, режима и ручной настройки.
- **Диагностика доставки** создаётся для каждого управляемого устройства как диагностический датчик, отключённый по умолчанию. Он показывает последний результат доставки климатических команд в текущем запуске и последнюю цель, полную последовательность служб для которой принял Home Assistant, без исходного текста ошибки и без утверждений о действиях физического устройства.
- **Начало предварительного прогрева** — датчик времени рассчитанного начала следующего или уже активного раннего блока. Атрибуты включают запланированное целевое время, опережение, направление, источник модели, целевую температуру и режим HVAC.
- **Room Assist** показывает текущее рабочее состояние Room Assist и компактный контекст цели без дублирования исходных показаний комнаты и устройства.
- **Автоматическое расписание** и **Режим** — доступные для изменения управляющие сущности Velair. Выключение автоматического расписания останавливает выполнение бессрочно; включение возобновляет активное расписание. Выбор пользовательского режима активирует связанные профили, а **По умолчанию** очищает активный набор. **Ручной** означает, что пользовательский режим не управляет активным набором профилей; прямая активация обычно включает это состояние. Velair показывает его, а не предлагает как действие. Для временной паузы с длительностью используйте действие `velair.pause`.

Эти сущности используют снимки бэкенда, получают обновления через dispatcher и не опрашивают Home Assistant. События удобны для реакции на переходы, а сущности — когда автоматизации или панели нужно узнать текущее состояние. Room Assist может скорректировать отправляемую цель после принятой управляющей цели; контекст такого применённого изменения предоставляется отдельным датчиком **Room Assist**. Полный список датчиков с основными атрибутами и примерами см. в [Справочнике датчиков](sensors.ru.md). Подробные правила управления, комфорта, проветривания и доставки см. в [Датчиках управления зоной и доставки команд](zone-sensors.ru.md).

При удалении климатического устройства из параметров интеграции Velair его созданные датчики зоны удаляются из реестра сущностей Home Assistant после перезагрузки. Глобальные сущности Velair и сущности других интеграций не затрагиваются. Повторное добавление устройства создаёт датчики заново с детерминированными уникальными ID.

Home Assistant выбирает переведённые имена сущностей по языку бэкенда при первом создании сущности. Смена только языка интерфейса одного пользователя не переименовывает существующие записи реестра. Сущности можно переименовать вручную в Home Assistant, не меняя их поведение в Velair.

<a id="open-velair"></a>
## Открыть Velair

После настройки Velair появляется в боковом меню Home Assistant.

Рекомендуется использовать боковую панель. Дополнительная карточка Lovelace полезна, если вы хотите встроить отдельные панели Velair в существующую панель управления.

В панелях типа «Разделы» карточки Velair используют автоматическую высоту, чтобы раскрытые элементы управления, дополнительные зоны и многострочный текст занимали место над следующей карточкой. Если после обновления существующая карточка по-прежнему перекрывает другую, проверьте её YAML в панели: удалите числовое значение `grid_options.rows` или замените его на `auto`. Сохранённые параметры размещения имеют приоритет над настройками карточки по умолчанию:

```yaml
grid_options:
  columns: 12
  rows: auto
```

Список следующих событий Обзора и карточки событий показывают следующую прогнозируемую смену управления каждой зоны, включая расчётную подготовку и прибытие при подтверждённом возвращении. Общий компактный формат: имя/источник/время/действие/HVAC без подзаголовка состояния под именем. Конечный значок информации объясняет фазу, режим прибытия, приостановку и текущую недельную справку, когда возвращение имеет приоритет. Помощь открывается наведением, фокусом или касанием. Приостановка объясняет блокировки, а не обещает заблокированное начало. Датчики следующего события и виды недельного опережения сохраняют недельное значение. Прогноз не меняет выполнение расписания и не подтверждает доставку команд.

Обзор зон использует компактные адаптивные карточки, показывающие, что сейчас делают Velair и климатическое устройство в каждой комнате. Если сущность сообщает `hvac_action`, основным состоянием становится её текущая работа: обогрев, охлаждение, осушение, вентилятор, ожидание, выключено, предварительный прогрев или размораживание. Затем та же сводка показывает состояние Velair — расписание, ручное управление, форсированный режим, пауза, подготовка или отключённая автоматизация —, сообщённый режим HVAC и важное время, не повторяя активность отдельным индикатором. Если `hvac_action` отсутствует или недопустим, Velair показывает собственное рабочее состояние, не предполагая действия устройства. Каждая карточка сначала показывает имя и ID сущности, затем активный профиль и упорядоченные индикаторы Room Assist/комфорта/воздуха/данных. В очень широких карточках эти индикаторы и компактная сводка делят заголовок. В узких карточках, в том числе на мобильных устройствах и в компактных представлениях Lovelace, имя устройства и компактное состояние остаются рядом, а индикаторы занимают всю строку ниже. Индикаторы профиля, возвращения, Room Assist и комфорта/воздуха/данных имеют компактную типографику и разделение значка/подписи и значения. Возвращение использует приглушённый фиолетовый; комфорт различает норму, информацию, предупреждение и ошибку. Длинные значения могут визуально сокращаться для сохранения высоты; полный текст доступен наведением, фокусом или касанием. Сводка использует единообразный значок, сбалансированный текст и сдержанный акцент активности без постоянного заголовка или внешней декоративной плашки. Когда Room Assist активен или удерживает температуру, детали сгруппированы как Температура (устройство, затем датчик), Уставка (устройство, затем расписание) и Смещение с учётом направления. Отсутствующие значения не показываются. Нейтральные индикаторы ненавязчивы; цвет предупреждения используется только для условий, требующих внимания.

Карточка Lovelace поддерживает следующие значения `view`:

- `climate`;
- `overview-status`;
- `overview-boosts`;
- `overview-events`;
- `overview-timeline`;
- `overview-zones`;
- `active-setup`;
- `schedules`;
- `sensors`;
- `comfort`;
- `preconditioning`;
- `planned-return`;
- `diagnostics`.

<a id="planned-return-card"></a>
### Карточка запланированного возвращения

Добавьте в любую панель те же элементы управления возвращением домой, что используются в боковой панели:

```yaml
type: custom:velair-card
view: planned-return
```

При обычном ожидающем уходе строка таймера объясняет проверку пустого дома и показывает срок бэкенда по местному времени Home Assistant. Режим отсутствия активируется только после подтверждения, если все источники по-прежнему сообщают отсутствие. До подтверждения нет текущего обратного отсчёта или временной шкалы ухода. С **Применить режим отсутствия сейчас** режим отсутствия и его временная шкала начинаются сразу; подтверждение ухода отдельно разрешает автоматическое возвращение по присутствию, пока подготовка и прибытие по расписанию остаются активными.

Визуальный редактор карточки называет это представление **Запланированное возвращение**. Оно показывает только компактные элементы **Разовое возвращение** (разовое возвращение), а справа вверху заголовка — число источников, сообщающих присутствие, отсутствие и неизвестное состояние. Сохранённая задержка подтверждения отсутствия появляется там только до активного подтверждённого отсутствия. Если источники присутствия не сохранены, индикаторы не показываются: **Запланировать возвращение** (запланировать возвращение) явно подтверждает уход и сразу активирует режим отсутствия без ожидания. Сохранённое прибытие по-прежнему управляет подготовкой и активацией конфигурации назначения; без источников Velair не обнаружит физическое прибытие. Настроенные неизвестные/недоступные источники сохраняют обычное ожидание, если не выбрано **Применить режим отсутствия сейчас**; для недельной процедуры необходимы источники. Задайте будущую дату и время возвращения до ухода или уже находясь вне дома. Активный эпизод предлагает только **Отменить это возвращение** и **Изменить время возвращения**. Отмена останавливает автоматизацию возвращения и восстанавливает предыдущий выбор режима/профилей после подтверждённого ухода или немедленного ручного применения режима отсутствия, даже до подтверждения отслеживаемого ухода. Обычное ожидающее подтверждение не меняет выбор. Например, исходный режим Комфорт и задержка пять минут: отмена через две минуты оставляет Комфорт активным; отмена после применения режима отсутствия восстанавливает Комфорт и его исходные профили. См. [примеры отмены](planned-return.ru.md#cancelling-a-return-examples), включая запуск без датчиков, редактирование прибытия и явный выбор режима. После завершения или отмены карточка показывает новую форму даты/времени, даже если состояние присутствия всё ещё говорит, что все вне дома. **Запланировать возвращение** остаётся видимой, но недоступной, если сохранённая конфигурация или планировщик недоступны. Боковая панель использует те же кнопки отмены/изменения времени и новую форму планирования. Только завершающие индикаторы присутствия/задержки специфичны для карточки; боковая панель сохраняет полную недельную конфигурацию, настройки присутствия и подготовки. Оба представления показывают компактный подзаголовок фазы рядом с заголовком и контекстную помощь с её объяснением. Во время подтверждения этот контекст даёт заголовок процесса. До подтверждённого ухода доступный значок прибытия и подпись **Ожидаемое прибытие** (ожидаемое прибытие) обозначают сохранённое возвращение, выровненные с заголовком/состоянием; сохранённое значение — компактная нажимаемая плашка без карандаша и подчёркивания. Подтверждённый график использует тёмное поле прибытия с типографикой ухода, без карандаша и подчёркивания. Оба варианта открывают один редактор прибытия. Синяя кнопка **Назад** со стрелкой влево в строке действий редактора отменяет правку прибытия и закрывает редактор локально, восстанавливая последнее сохранённое прибытие. Её предупреждение и защита перехода снимаются; независимые несохранённые настройки процедуры остаются защищены. Повторное открытие начинает с сохранённого значения. Успех закрывает редактор, а ошибки сохранения и текущие обновления сохраняют черновик. Время ухода и прибытия используют одинаковую типографику; Отмена — компактная красная кнопка с белым текстом слева под данными эпизода, видимая только когда активное возвращение можно отменить и редактор закрыт. При редактировании **Назад** закрывает редактор слева, а изменение времени остаётся справа на компактной зелёной поверхности. Обе кнопки имеют видимую поверхность 32 пикселя внутри области касания 44 пикселя. Индикаторы присутствия карточки остаются справа вверху заголовка; индикатор задержки исчезает после подтверждённого ухода.

Настройте источники присутствия, режимы, подтверждение отсутствия и недельную процедуру в разделе **Предварительный прогрев > Запланированное возвращение** боковой панели. Карточка использует эту сохранённую конфигурацию дома; в ней нет полей настройки или переключателя недельной процедуры. Фильтры показа термостатов не ограничивают эту карточку для всего дома. Элементы панели и боковой панели обновляют один эпизод бэкенда; черновики прибытия остаются локальными в каждой открытой карточке до отправки.

Сохранённое время ухода и редактируемого прибытия расположено над шкалой, подписи режимов отсутствия и назначения — под ней. Даты используют одинаковую типографику; прибытие оформлено как более тёмное поле для открытия редактора без карандаша и подчёркивания. Отдельные подсказки ухода, значка прибытия и режимов открываются наведением, фокусом или касанием. Нейтральная вертикальная риска **Сейчас** совпадает с концом истекшего отрезка времени UTC. Даты появляются, если концы относятся к разным дням в часовом поясе Home Assistant. Черновик прибытия не сдвигает сохранённую шкалу до принятия. Ожидающие и итоговые состояния или отсутствие подтверждённого ухода не имеют движущейся шкалы; активная ошибка с корректным уходом сохраняет шкалу и отмену. Локальные часы обновляются раз в минуту только при видимой активной карточке или панели, в том числе после повторного появления; сервер при этом не опрашивается.

Каждый подходящий адаптивный термостат имеет цветную точку подготовки размером 8 пикселей, соответствующую кругу легенды и соответствующую легенду с именем и расчётным началом под ним. Время использует часовой пояс и формат 12/24 часа Home Assistant, с датой для более позднего дня. Подсказки сохраняют полное имя и фактическую оценку. Совпадающие точки образуют круг с равными цветными секторами. Легенда дома начинается с одной строки с визуально сокращёнными длинными именами; кнопка дополнительных термостатов раскрывает её внутри панели, а **Показать меньше** сворачивает. Обычные обновления сохраняют раскрытие; изменение сохранённого прибытия, назначения или эпизода сбрасывает его и удаляет устаревшие оценки. Раскрытие не меняет возвращение и не выполняет переход.

Приостановленные, достигшие цели, недоступные помещения и помещения с действием только при прибытии не получают точек. Точка до границы ухода располагается на краю, а подсказка сохраняет фактическое время. Шкала измеряет истекшее время, а не тепловой прогресс или физическую работу HVAC. Отсутствие оценки не означает отключённую подготовку: подсказки объясняют известное состояние без выдуманного времени. Правка прибытия сохраняет принятую проекцию; Назад возвращает сохранённое прибытие. Отмена и изменение прибытия остаются доступны.

<a id="climate-status-and-control-card"></a>
### Карточка состояния и управления климатическим устройством

Используйте `view: climate` для компактной карточки одной управляемой Velair сущности `climate.*`. Она следует активной теме Home Assistant через переменные цветов и поверхностей и адаптируется к светлому, тёмному, мобильному, планшетному и настольному представлению.

Карточка объединяет сообщаемые устройством температуру, влажность, режим HVAC и `hvac_action` с текущими данными управления и работы Velair. Она использует ту же действующую дневную шкалу, значок и цвет профиля, что вкладка Обзор. Информация о режиме, профиле, комфорте, Room Assist и подготовке показывается только когда настроена и уместна. Устройство с внешним выполнением показывает внешнего поставщика и состояние публикации вместо локальных функций Velair или действий конкретного устройства. Необязательное действие разового возвращения управляет всем домом и независимо от того, кто управляет выбранным устройством.

```yaml
type: custom:velair-card
view: climate
selected_entity: climate.living_room
climate_name: Living room
climate_humidity_entity: sensor.living_room_humidity
climate_outdoor_temperature_entity: sensor.outdoor_temperature
climate_window_entities:
  - binary_sensor.living_room_window
  - binary_sensor.patio_door
climate_window_display: grouped
climate_room_assist_display: both
climate_preconditioning_display: both
climate_show_control_mode: true
climate_show_target_control: true
climate_show_hvac_mode_control: true
climate_show_native_climate_link: true
climate_actions:
  - type: boost
  - type: pause
    placement: more
  - type: planned-return
    enabled: true
  - type: script
    name: Ventilate room
    script: script.ventilate_living_room
    icon: mdi:window-open-variant
    color: "#03a9f4"
    confirmation: true
    placement: auto
```

Область управления объединяет упорядоченные быстрые действия с отдельно настраиваемым переключателем автоматического/ручного управления, используя ту же модель владения управлением, что Обзор. Нижняя область объединяет режим HVAC, текущую цель при включённом устройстве и ссылку на нативное окно климатического устройства Home Assistant. Каждый публикуемый режим HVAC показан со значком. Прямые изменения доступны только для чтения, пока Velair управляет активным расписанием: сначала выберите **Вручную**, дождитесь подтверждения ручной настройки, затем используйте элементы температуры и режима. Выберите **Автоматически**, чтобы возобновить расписание. Форсированный режим, независимые паузы, остановка и недоступность блокируют прямое редактирование с пояснением. Внутренняя пауза самой ручной настройки не блокирует эти элементы. Зоны с внешним выполнением сохраняют нативную ссылку Home Assistant; включённое действие разового возвращения всё равно может открыть управление уходом для дома.

Поддерживаются одна температура и нативные диапазоны `heat_cool`. Изменение диапазона отправляет обе границы вместе. Velair использует `min_temp`, `max_temp` и `hvac_modes`, публикуемые климатической сущностью. Изменения цели используют `target_temp_step`, когда он опубликован. Если атрибут исчезает, Velair продолжает использовать последний допустимый сообщённый шаг, сохраняя допустимость существующих дробных целей. Следующим идёт ручное резервное значение зоны в Настройках, затем `1`, если шаг никогда не сообщался и не настраивался. Velair не придумывает режимы HVAC.

Карточки, созданные до упорядоченного списка действий, использовали `climate_show_boost_action`, `climate_show_pause_action` и `climate_custom_actions`. Velair продолжает читать эти старые поля, а визуальный редактор записывает `climate_actions` при изменении списка.

**Разовое возвращение** — ещё одно действие Velair. Оно поддерживает те же параметры видимости, скрытия имени и автоматического размещения или размещения в меню Ещё, что форсированный режим и пауза. Редактор сначала перечисляет встроенные действия: форсированный режим, паузу, затем разовое возвращение, включая скрытые действия. Разовое возвращение использует фиолетовый акцент для отличия от паузы. Открытие заменяет нижнюю область управления компактной формой ухода или шкалой и элементами текущего эпизода. Закройте область её X, чтобы вернуться к климатическим элементам; закрытие не отменяет активный уход. Несохранённые правки прибытия требуют подтверждения перед закрытием, а ожидающее действие сначала должно закончиться. Настройки и последствия ухода применяются ко всему дому, не только выбранному устройству.

Области форсированного режима, паузы и разового возвращения соединяются с рамкой и поверхностью панели действий, как обычные элементы термостата. Прямые действия только со значком сохраняют компактную ширину и центрируют значок; открытие области добавляет место для значка закрытия.

Существующие карточки оставляют это действие скрытым, пока его не включат явно. Карточки, созданные через выбор карточек Home Assistant, включают его в начальный список; это также действует при смене представления новой карточки на `climate`. YAML-карточка без действия `planned-return` оставляет его скрытым. Включите его в визуальном редакторе или добавьте действие, показанное выше.

Редактор сохраняет встроенные действия в фиксированном разделе и предлагает упорядочивание пользовательских действий. Открытие редактора не меняет порядок сохранённого списка действий панели.

По умолчанию текущая влажность и ссылка на её историю используют атрибуты выбранной климатической сущности. Задайте `climate_humidity_entity`, чтобы вместо них использовать текущее значение и нативную историю отдельного датчика влажности Home Assistant. Velair не выводит эту связь сам, поскольку интеграции Home Assistant не публикуют её единообразно.

Наружная температура и сущности окон — необязательный контекст панели. Через эту карточку Velair не обнаруживает их, не управляет ими и не автоматизирует их. Состояния окон только информативны, в том числе когда отдельная автоматизация или [шаблон окон](blueprints/pause-zone-for-open-windows.ru.md) Velair использует эти сущности. Задайте `climate_window_display` как `grouped` или `individual`; визуальный редактор даёт отдельные флажки наружных показаний и окон и не показывает раздел до выбора сущности. Весь заголовок текущего состояния сворачивает развёрнутую область. Компактные показания и контекст используют переносящиеся плашки вместо горизонтальной прокрутки, сохраняя видимость всех включённых датчиков при малой ширине. Доступная оценка комфорта занимает отдельную описательную строку под свёрнутым заголовком с состоянием, пояснением комфорта, значком и акцентом состояния. Редактор может показывать включённые производные показатели комфорта в этой свёрнутой строке; иначе они остаются в развёрнутой строке. Строка комфорта отсутствует при недоступной оценке. Элемент раскрытия остаётся на месте, пока плашки занимают столько компактных строк, сколько требует ширина карточки. Это состояние представления хранится только в текущей сессии карточки. Текущее состояние изначально свёрнуто. Визуальный редактор позволяет начать развёрнутым; изменение этого значения по умолчанию не запрещает ручное сворачивание или раскрытие.

Визуальный редактор следует порядку карточки сверху вниз. Он может независимо скрывать полосу состояния, имя устройства, рабочее состояние, отдельные элементы термостата и действия, текущую температуру, влажность, наружные показания, окна, комфорт, необязательные свёрнутые показания комфорта, шкалу, Room Assist и подготовку. Имя устройства также можно заменить независимой локальной подписью карточки, в том числе пустой, и вернуть к текущему понятному имени сущности. Если все элементы текущего состояния отключены, вся область отсутствует. Неуказанные значения видимости считаются включёнными, сохраняя вид существующих карточек. Каждое видимое показание текущей температуры или влажности содержит компактную ссылку на нативную историю настроенного источника Home Assistant; ссылка скрывается вместе с показанием. Каждую категорию настройки можно свернуть; отдельные пользовательские действия скриптов остаются свёрнутыми до необходимости редактирования, делая редактор удобным на узких экранах. Выбор другого скрипта обновляет имя ссылки из его сущности; после этого имя снова можно изменить. Ссылка Velair в заголовке присутствует всегда, чтобы карточку можно было узнать и последовательно вернуться к интеграции. Каждое прямое действие может скрыть видимое имя и стать кнопкой размером со значок; доступное имя и полное имя в меню Ещё сохраняются.

Быстрые действия делят верхнюю строку области управления с переключателем автоматического/ручного управления. Они остаются отдельной группой на противоположном конце той же строки при любой ширине. Если подписи не помещаются, они сохраняют полную естественную ширину, а группа прокручивается горизонтально вместо переноса или обрезки. Открытие форсированного режима или паузы заменяет обычную область термостата на месте; Отмена или повторное нажатие выбранного действия возвращает обычные элементы. Нативная полоса прокрутки скрыта. При переполнении направляющие элементы занимают фиксированные внешние места и видны только пока вне экрана остаются действия, не перекрывая и не меняя размер строки; когда всё помещается, места полностью убираются. Строка поддерживает свайп и перетаскивание мышью или пером без выполнения действия, с которого начато перетаскивание. Действия скриптов кратко подтверждают принятую команду или ошибку на самой кнопке, а открытый форсированный режим или пауза показывает значок закрытия.

Заголовок климатического устройства использует текущую рабочую активность как главный визуальный сигнал и объединяет активность, источник выполнения и режим HVAC под именем устройства. Компактная подпись Velair остаётся ссылкой на главную панель, сохраняя имя проекта и автора на двух строках при любой ширине.

Разделы шкалы и Room Assist используют соответствующие графики Velair, включая горизонтальную прокрутку на узких экранах. Задайте `climate_room_assist_display` как `text`, `chart` или `both`, чтобы показывать краткое пояснение текущего состояния, график температуры или оба. Состояние Room Assist всегда остаётся рядом с заголовком, а пояснение занимает вторую строку, когда включено. Сворачиваются только представления с графиком; текстовый режим остаётся видимым без вводящего в заблуждение элемента раскрытия.

`climate_preconditioning_display` следует той же модели `text`, `chart` или `both`. Принятая подготовка к возвращению отличается от недельного опережения: состояние помещения, расчётное начало, цель прибытия и причина. Они описывают сохранённое возвращение и намерение управления, а не физическую работу. Встроенное разовое возвращение показывает только подходящую точку выбранного термостата с именем и расчётным началом в легенде, без значков подготовки. Если текущей точки нет, шкалу заменяет краткая причина. Прибытие редактируется, отмена доступна; действия относятся ко всему дому. Шкала измеряет время до прибытия, а не тепловой прогресс. Заголовок сохраняет видимым запланированное или активное состояние, а необязательная вторая строка указывает цель и рассчитанный старт. В режиме только графика над раскрываемым предпросмотром остаётся лишь состояние. Оба графических раздела изначально свёрнуты, если не настроено иначе; параметр начального состояния показан в редакторе только при выборе графика. Заголовок шкалы, активный профиль и активный режим сохраняют свои параметры видимости; плашки режима и профиля имеют уменьшенную высоту для карточки. Ручное раскрытие хранится локально в текущей сессии карточки.

Форсированный режим открывает форму в карточке со всеми параметрами, поддерживаемыми устройством и службой: цель или диапазон, длительность, режим HVAC, вентилятор, предустановка, качание, горизонтальное качание и влажность. Пауза позволяет выбрать конечную или бессрочную длительность и оставить устройство как есть или выключить. Карточка не предоставляет `pause_id`, зарезервированный для обозначения причин автоматизаций. Когда пауза может принадлежать другому владельцу или причине, карточка открывает Velair вместо неявного удаления причин. Ручное управление можно вернуть к автоматическому из карточки. Эти локальные действия никогда не показываются для зон с внешним выполнением. Форсированный режим и паузу/возобновление можно скрывать независимо и перемещать в том же упорядоченном списке действий, что ссылки скриптов. Их поведение, подписи, значки и формы задаёт Velair; менять их нельзя.

Список действий также может включать выбранные пользователем сущности `script.*` Home Assistant. Каждая ссылка имеет локальное для карточки имя, значок MDI, цвет и необязательное подтверждение. Velair хранит только эти параметры представления в карточке Lovelace и запускает выбранную сущность через `script.turn_on`; сам скрипт, его разрешения и действия остаются под управлением Home Assistant. Карточка не принимает произвольный JavaScript, шаблоны, данные служб или встроенные последовательности действий. Поэтому скрипты должны запускаться без обязательных входных полей; определите нужные значения в скрипте Home Assistant или задайте там значения по умолчанию. Каждое действие может использовать `placement: auto` или `placement: more`. Автоматически размещаемые действия занимают первые три доступные прямые позиции, а остальные попадают в **Ещё**. Действия с `more` всегда остаются в этом меню независимо от позиции в упорядоченном списке. Предел в три позиции фиксирован, а не является дополнительной настройкой. **Ещё** отсутствует, если не содержит действий; **Открыть Velair** остаётся последним фиксированным пунктом и само по себе не создаёт меню. Ссылки скриптов доступны для внешних зон, поскольку это независимые действия Home Assistant, а действия только Velair сохраняют обычные ограничения управления и доступности.

Тонкая линия сверху обозначает рабочее состояние, не прогресс. Обогрев и предварительный прогрев используют тёплый акцент, охлаждение — холодный; осушение и вентилятор остаются неподвижными, ожидание — приглушённый вариант активного режима, выключение — нейтральное, недоступность — прерывистое обозначение ошибки. Движение — краткий сигнал смены состояния; оно отключается при предпочтении уменьшенного движения. Режим HVAC `off` имеет приоритет над устаревшей активностью `idle`, поэтому карточка показывает **Выключено** со значком питания; ожидание при выбранном активном режиме использует нейтральный значок термостата и не похоже на паузу Velair.

Карточки Lovelace по зонам также могут ограничить показываемые термостаты. Это только фильтр отображения панели; он не меняет сохранённые расписания или поведение планировщика. Глобальные карточки, например `overview-status` и `active-setup`, не показывают выбор термостатов или дня недели в редакторе, поскольку не связаны с одним термостатом или редактором расписания.

Добавляйте `view: active-setup` независимо от карточки состояния планировщика. Используйте визуальный редактор или `active_setup_controls`, чтобы выбрать, может ли активная конфигурация менять `modes`, `profiles` или `both`:

```yaml
type: custom:velair-card
view: active-setup
active_setup_controls: profiles
```

По умолчанию `both`; каждый вариант показывает **Базу** и **Исключения**, действительный тип и имя базы режима/профиля/настроек по умолчанию и числа зон исключений. База и тип находятся в небольшой строке над именем; длинные имена переносятся на телефонах и узких карточках. Покрытие базы считает только ещё наследующие её зоны, без исключений и настроек по умолчанию вне профиля. База по умолчанию включает все зоны. Это выбор, а не работа устройств.

**Распределение по дому** под базой изначально свёрнуто. Нажатие заголовка показывает полосу и всю легенду; повторное нажатие или Escape скрывает, сохраняя заголовок на месте. Полоса охватывает все управляемые зоны с общим числом в подписи, цветами профилей, небольшими значками и правым столбцом чисел. Исключения совпадают со списком, включая зоны вне базы. Неохваченные зоны без исключений образуют нейтральный сегмент по умолчанию. Общее число дома отделено от покрытия базы; без управляемых зон полосы нет. Профили базы указаны в легенде без дополнительного списка режима. Широкий вид даёт больше места исключениям, узкий складывает сводку вертикально.

Нажмите любое место строки исключения для раскрытия помещений под ней. Повторное нажатие или Escape сворачивает, открытие другой группы закрывает предыдущую. Строка и число остаются на месте, содержимое растёт вниз, длинные списки прокручиваются внутри. Другие исключения видны. Подробности доступны только для чтения во всех вариантах, отдельного редактора зон нет. Вид профилей имеет возврат к расписаниям по умолчанию. Прямой профиль заменяет всю базу и выбирает Manual; зоны вне него возвращаются к настройкам по умолчанию. Режим объединяет непересекающиеся профили как базу. Слои применяют профиль только к настроенным зонам как исключения, сохраняя другие выборы. См. [базу и исключения](climate-profiles.ru.md#a-base-with-independent-zone-exceptions).

```yaml
type: custom:velair-card
view: preconditioning
entities:
  - climate.living_room
  - climate.bedroom
zone_order:
  - climate.bedroom
  - climate.living_room
```

Если `entities` отсутствует, карточки по зонам показывают все управляемые Velair термостаты.

Для `view: sensors` редактор карточки позволяет скрыть переключатель включения, выбор датчика комнаты, зону нечувствительности Room Assist, максимальную коррекцию, задержку обновления или текущий статус, чтобы карточка только показывала данные или занимала меньше места.

Для `view: comfort` редактор может ограничить карточку выбранными термостатами и независимо скрыть раздел настройки, график температуры, влажности или CO2. Это только параметры представления панели; они не меняют настройки комфорта, отслеживаемые датчики, пороги, события или созданные сущности Home Assistant.

```yaml
type: custom:velair-card
view: comfort
entities:
  - climate.living_room
show_comfort_configuration: false
show_comfort_temperature: true
show_comfort_humidity: false
show_comfort_co2: true
```

<a id="create-a-daily-schedule"></a>
## Создать дневное расписание

При входе в **Расписания** Velair открывает текущий местный день недели. Затем выбор сохраняется при переходе между термостатами, расписаниями по умолчанию и профилей или при обновлении данных бэкенда.

1. Выберите климатическое устройство для настройки.
2. Выберите **Группировку дней**, затем день или группу.
3. Используйте **Собственное расписание** для независимых блоков либо выберите шаблон с **Только время** или **Время и настройки**. Для независимых блоков продолжайте ниже.
4. Добавьте блок.
5. Выберите время начала.
6. Выберите режим HVAC или оставьте `Сохранить режим`.
7. Введите целевую температуру или диапазон либо выберите климатические параметры без цели.
8. Сохраните.

В дополнительных настройках **Пресет Velair** может задать климатическую конфигурацию блока, оставляя время независимым. Связанные дни следуют выбранному объёму связи шаблона. До выбора между копированием и связыванием см. [полные правила](linked-schedules.ru.md) и [практические примеры для дома](linked-schedule-examples.ru.md).

После явного выбора режима HVAC, отличного от выключения, нажмите компактную кнопку термометра в ячейке цели, чтобы отключить ввод температуры. Серое поле покажет тире, а блок вызовет только службу `climate.set_hvac_mode` Home Assistant без отправки одной температуры или диапазона. Это полезно для режимов вроде `auto`, в которых интеграция или устройство может возобновить собственную программу, но доступно для любого сообщаемого сущностью режима HVAC, кроме выключения. Та же кнопка снова включает ввод; Velair восстанавливает предыдущую цель черновика, которая должна быть допустима перед сохранением расписания. Существующие блоки сохраняют текущее поведение цели.

Блоки только с режимом не выполняют подготовку или Room Assist, поскольку у Velair нет температурной цели для достижения или коррекции. Необязательные климатические настройки тоже недоступны, чтобы сохранённое действие оставалось одним однозначным изменением режима HVAC. Внешние поставщики расписания должны явно сообщать поддержку этого действия; Velair никогда не преобразует его в температурный блок.

Чтобы запланировать предустановку или другой климатический параметр без целевой температуры, выберите параметр в дополнительных элементах блока и отключите ввод цели. Блок может объединять предустановку, вентилятор, качание, горизонтальное качание и целевую влажность. Он вызывает только соответствующие климатические службы Home Assistant; не отправляет `climate.set_temperature`, не меняет режим HVAC и не включает выключенное устройство. Блок должен содержать хотя бы один поддерживаемый параметр. Прямые изменения этих параметров между событиями расписания не восстанавливаются Velair немедленно. Блоки только с параметрами не выполняют подготовку или Room Assist. При нескольких элементах Home Assistant получает отдельные вызовы служб последовательно. Если поздний вызов не удался, предыдущие параметры уже могли измениться; Velair сообщает об ошибке доставки.

При применении шаблона или профиля к другому устройству Velair сохраняет поддерживаемые им параметры. Если в блоке только с параметрами ничего не осталось, расписание назначения отклоняется вместо сохранения пустого действия.

При редактировании расписания Velair использует возможности выбранной климатической сущности. Неподдерживаемые режимы не предлагаются, а температура ограничивается диапазоном сущности.

В температурном блоке `Сохранить режим` отправляет цель и выбранные климатические параметры без запроса другого режима, пока устройство включено. Если оно выключено, Velair запускает его в первом поддерживаемом режиме, совместимом с целью. Блок сохранения режима можно сохранить, когда устройство объявляет хотя бы один режим кроме выключения, совместимый с типом цели; это не гарантирует совместимость рабочего режима к моменту выполнения блока. Если текущий режим не принимает цель, доставка завершается ошибкой без переключения на другой режим. Некоторые интеграции объявляют поддержку одной целевой температуры только после запуска режима, поэтому Velair сначала запускает совместимый режим, затем отправляет цель и позволяет службе Home Assistant сообщить об ошибках конкретного устройства. Нативный диапазон по-прежнему требует явной поддержки диапазонов; Velair никогда не превращает одну цель в диапазон или диапазон в одну цель.

Редактор сохраняет выбранные климатические параметры видимыми в компактной строке. Для блока с параметрами откройте его элемент параметров, чтобы увидеть, что будет отправлено: цель при наличии, обработка режима HVAC и выбранные параметры. Пояснение также уточняет, что одна температура не превращается в диапазон. Это работает в расписаниях, профилях и шаблонах. Редактор предупреждает, не блокируя сохранение, если более ранний блок того же дня выбирает режим, который может не принимать тип цели. Если предыдущий явный режим или блок выключения не определяет режим, для подсказки используется текущий режим устройства. Он может измениться до выполнения блока, поэтому предупреждение условное.

Температурные блоки содержат одну цель или полный диапазон с нижней и верхней целями. Редактор использует возможности, публикуемые климатической сущностью, и по умолчанию создаёт новые блоки `heat_cool` с диапазоном при поддержке. Диапазон показан, например, как `20–24 °C`. Velair не придумывает диапазон из одной температуры и отклоняет неполные, перевёрнутые или несовместимые цели перед отправкой команды.

На этом этапе нативные диапазоны ограничены `heat_cool`. Velair не предполагает, что режим `auto` устройства использует ту же модель нижней и верхней цели.

Если выбранное устройство предоставляет дополнительные элементы, редактор блока показывает и их. Например, кондиционер может предоставлять режим вентилятора, предустановку, качание, горизонтальное качание или влажность. Velair сохраняет и отправляет только параметры, поддерживаемые выбранным устройством; неподдерживаемые отбрасываются вместо отправки без проверки.

Если блок использует `Выкл.`, поля цели не используются, поскольку блок выключает климатическую сущность.

Выберите **Только температура** в селекторе режима блока для изменения цели без запроса включения или смены HVAC. Выключенный термостат остаётся выключенным, если интеграция принимает цели в этом состоянии; работающий сохраняет фактический режим. Это отдельный вариант: **Сохранить текущий режим**, явные режимы и сохранённые расписания сохраняют поведение. Блоки только температуры не могут содержать дополнительные параметры, например пресет, способные изменить состояние устройства.

Политика действует весь блок, включая ручные изменения HVAC, запуск, возобновление и восстановление доставки. Смена только HVAC не начинает ручную корректировку; изменение температуры следует политике внешних изменений. Room Assist и предварительная подготовка не работают при выключенном термостате; могут возобновиться после внешнего включения с текущим совместимым режимом. Явное усиление — отдельный запрос, который может включить устройство.

Поддержка зависит от интеграции: некоторые скрывают или отклоняют цели при выключении либо сами включают устройство при получении цели. Velair не отправляет смену режима или включение как запасной вариант и не включает устройство ненадолго для установки цели; ошибка сообщается. Нативные диапазоны требуют поддержки диапазона. Внешний провайдер расписания должен явно поддерживать эту политику.

**Группировка дней и редактирование нескольких дней**

Расписание по умолчанию каждой зоны и её расписание в профиле запоминают собственную **Группировку дней**: **Отдельные дни**, **Будни / Выходные**, **Все дни**. Существующие расписания начинаются с отдельных дней. Семь ячеек сохраняют настроенный порядок недели; нажатие выбирает один день, понедельник–пятницу, субботу–воскресенье или всю неделю. При первом воскресенье выходные охватывают оба конца полосы. Соседние выбранные ячейки соединены визуально; разделённые сохраняют позиции. Нажатие уже выбранной группы сохраняет черновик.

Выбор группировки сохраняет блоки; сохраните его с расписанием по умолчанию или полным профилем. Каждая зона может иметь свой вариант, а шаблоны остаются дневными списками. Одинаковые настройки выбранных дней редактируются вместе. При различиях **Разные расписания** показывает альтернативы; одинаковые блоки и связи сгруппированы с метками дней. Альтернативы используют компактные полосы Обзора с целью и режимом без постоянного списка блоков. Значок информации открывает время, настройки и ссылки наведением, фокусом или касанием, не выбирая основу. Выберите альтернативу нажатием либо стрелками, Пробелом и Enter; фон и рамка обозначают единственную основу, остальные доступны до сохранения.

Для всех дней или будней/выходных сначала выберите и сохраните основу для семи, пяти или двух дней. Сохранение применяет её без дополнительного подтверждения; общий редактор блоков открывается только после успеха. Ошибка сохраняет выбор и сравнение. Пустые альтернативы показывают **Нет собственных блоков** без лишнего нулевого счётчика; помощь объясняет удаление собственных блоков. Пустой день не выключает устройство: может продолжаться предыдущее расписание. Вид подходит для телефона.

Выбор основы ничего не сохраняет. Сохранение недоступно без неё и расположено под содержимым справа. Сводка указывает исходный день и получателей. Сохранение заменяет только дни группы, не меняя другие. Одинаковая видимая температура не означает одинаковые настройки: компактные метки указывают шаблон, объём связи, пресет или независимое расписание, полные ссылки — в помощи.

Добавление, удаление и перемещение блоков, применение шаблона, смена и снятие связи охватывают всю выбранную группу после сохранения. Сохранение как шаблона создаёт один дневной список. Копирование в другие термостаты охватывает те же дни недели, сохраняя группировку назначений. Копирование между днями требует **Отдельных дней**. Общая шкала показывает редактируемые блоки без отдельного выбора предпросмотра дня или унаследованного сегмента. Отдельные дни сохраняют непрерывность предыдущего дня. Недельная непрерывность не меняется, унаследованные блоки не копируются в сохранённые. Ограничения устройств проверяются для всех дней перед полным сохранением. Группировки переживают перезапуск и экспорт; старый импорт без группировки или прежние пользовательские ссылки открывают отдельные дни, сохраняя все блоки и связи.

## Редактирование временной шкалы

Временная шкала — визуальное представление 24 часов выбранного дня.

- Перетащите блок, чтобы сдвинуть его начало.
- Перетащите край блока, чтобы изменить интервал между соседними блоками.

<a id="preconditioning"></a>
## Предварительная подготовка

Для обнаружения отсутствия по источникам присутствия с заранее настроенными недельными или разовыми прибытиями см. [Запланированное возвращение](planned-return.ru.md). Настройте процедуру на вкладке запланированного возвращения и используйте текущий статус для состояний отдельных источников и изменения разового прибытия без редактирования сохранённой недели. **Запланировать возвращение** может ждать подтверждённого ухода с разовым временем, даже когда автоматическая недельная процедура отключена. Если источники присутствия не сохранены, явный запуск сразу применяет отсутствие; обычная подготовка и сохранённое прибытие всё равно выполняются.

В панели этот раздел называется **Предварительный прогрев**; функция поддерживает и обогрев, и охлаждение. Предварительная подготовка позволяет Velair начать применять запланированную комфортную цель раньше видимого времени блока для одного управляемого устройства.

При включении для устройства на вкладке подготовки время блока означает желаемое время комфорта. Velair может применить цель раньше по адаптивному прогнозу, оставляя исходное целевое время видимым в предстоящих событиях.

Если пересчёт происходит уже внутри окна подготовки, Velair немедленно применяет цель, когда текущая температура ещё требует обогрева или охлаждения.

Вкладка подготовки перечисляет управляемые устройства в порядке Настроек. Для каждого можно:

- включить или отключить подготовку;
- задать максимальное опережение до 1440 минут;
- задать параметры адаптивной модели и минимальную разницу температур;
- независимо посмотреть обучение обогреву и охлаждению;
- восстановить параметры настройки по умолчанию, не удаляя обучающие наблюдения;
- сбросить обучение одного направления, не затрагивая другое.

Настройки сгруппированы по времени и ограничениям, модели обучения, истории и необязательному наружному контексту. Когда наружный контекст отключён, выбор его датчика тоже отключён. Недоступные устройства не могут включить подготовку, и вкладка объясняет почему.

Каждый элемент настройки содержит компактную контекстную помощь. Наведите указатель, установите фокус или нажмите значок информации, чтобы узнать, как увеличение, уменьшение или включение параметра влияет на подготовку.

Подготовка адаптивна. Velair прогнозирует каждое будущее событие по текущей разнице температур: сначала по локальной начальной модели, затем по сходной локальной истории после накопления достаточных полных наблюдений. Исторические прогнозы изучают тепловой потенциал на градус, позволяя масштабировать небольшие прошлые изменения к большим будущим разницам, а большие — к меньшим. Более сходные и свежие наблюдения влияют сильнее.

Velair не начинает раньше блоки `Выкл.`. Если текущая температура достаточно близка к цели, сохраняется обычное время блока.

Для нативных диапазонов `heat_cool` Velair использует нижнюю границу, когда комнате нужен обогрев, и верхнюю, когда нужно охлаждение. Полный диапазон всё равно применяется раньше, а обучение записывает границу, определявшую сессию.

Подробные примеры настройки, обогрева, охлаждения, наружного датчика, автоматизаций и Lovelace описаны в [Адаптивной предварительной подготовке](adaptive-preconditioning.ru.md).

До раннего начала Velair отслеживает значимые изменения температуры управляемых устройств с включённой подготовкой. По умолчанию используется собственная `current_temperature` термостата. Если включён Room Assist по датчику комнаты, выбранный датчик становится фактической температурой комнаты для решений подготовки и обучения. Когда температура меняется достаточно для влияния на текущую разницу, Velair объединяет быстрые изменения и локально пересчитывает следующее действие планировщика. Открытые панели тоже объединяют значимые изменения внутренней или настроенной наружной температуры в одно обновление без постоянного опроса. Если раннее начало того же видимого события изменилось, строка кратко подсвечивается, позволяя заметить коррекцию без диалога или глобального уведомления.

<a id="room-assist"></a>
## Room Assist

Вкладка Room Assist перечисляет управляемые устройства в порядке Настроек. Для каждого можно настроить помощь по датчику температуры комнаты.

Выбранный комнатный датчик полезен для термоголовок и термостатов, чей встроенный датчик слишком близок к радиатору, выходу воздуха или другому местному источнику тепла. Один выбор датчика не меняет управление Velair. Он становится фактической температурой комнаты только при включённой помощи по датчику: Velair также корректирует цель термостата, чтобы исполнительное устройство продолжало обогрев или охлаждение по показаниям отдельного комнатного датчика.

Подробные примеры обогрева, охлаждения, автоматизаций и Lovelace описаны в [Room Assist](room-assist.ru.md).

Помощь по датчику комнаты — расширенная функция, требующая комнатного температурного датчика, но не требующая адаптивной подготовки. Для фиксированного блока `heat` или `cool` с ненулевой зоной нечувствительности Velair использует нижний и верхний края как границы переключения. Рабочая фаза сохраняется до достижения противоположного края отдельным датчиком, затем меняется: фиксированный обогрев безопасно начинается в направлении нижней границы, фиксированное охлаждение — верхней. Максимальная коррекция ограничивает поправку со знаком от текущего активного края. Зона нечувствительности `0` сохраняет прежнюю знаковую коррекцию вокруг центральной цели. Одна цель в `auto` и `heat_cool` сохраняет нейтральное поведение, а нативные диапазоны `heat_cool` — стабильную полосу удержания; Velair не заставляет автоматическое устройство активно чередовать обогрев и охлаждение. Зона нечувствительности по умолчанию — `0.3 °C` или `1 °F`; доступны шаги `0.1` градуса от `0` до `5 °C` или `9 °F`, применяемые сразу при сохранении. Максимальная коррекция по умолчанию — `2 °C` или `4 °F`, настраивается шагами `0.1` градуса до `10 °C` или `18 °F`. Видимая цель или диапазон расписания не меняются; выравнивание по шагу, защита расписания и физические пределы устройства действуют по-прежнему. Фаза существует только в текущем запуске и начинается заново после смены блока, цели или режима, очистки Room Assist или перезагрузки интеграции. Velair влияет через цель; он не отменяет гистерезис устройства, защиту компрессора или минимальное время работы. Для явного выключения используйте блок `Выкл.`.

Velair следует настроенной единице температуры Home Assistant. Отдельной настройки Celsius или Fahrenheit нет. Настройки показывают единицу Home Assistant только для чтения, чтобы проверить активное поведение; меняйте её в настройках системы единиц Home Assistant. Новые расписания, встроенные шаблоны, пороги комфорта, пределы Room Assist и значения адаптивной подготовки по умолчанию физически эквивалентны в обеих единицах. Показания отдельных температурных датчиков преобразуются до сравнения с целью устройства.

Velair хранит тепловые значения без преобразования в единице, записанной с данными. Если Home Assistant меняет единицу, Velair останавливает расписание и запись тепловых данных, создаёт постоянное уведомление и предлагает один явный перенос из сохранённой единицы в текущую единицу Home Assistant в Настройках. Продолжайте только если все сохранённые значения ещё используют показанную исходную единицу; уже преобразованные значения будут пересчитаны неверно. Расписания, шаблоны, цели текущих и предыдущих переопределений, пределы комфорта, Room Assist, настройки, скорости и обучающие наблюдения адаптивной подготовки переносятся атомарно.

Однократное обновление опубликованных данных Velair, поддерживавших только Celsius, отличается. Если Home Assistant уже использует Fahrenheit, Velair без запроса считает старые данные Celsius, оставляет планировщик остановленным и направляет к **Сбросить Velair**. Сброс удаляет прежнюю конфигурацию и атомарно создаёт новые исходные значения Fahrenheit. После обновления последующие изменения единицы Home Assistant используют описанное полное явное преобразование и сохраняют данные.

Текущие переносимые экспорты модели v19 сохраняют значения без преобразования и указывают единицу. Более ранние версии Velair не импортируют v19; восстанавливайте их версией с поддержкой v19. Старые поддерживаемые файлы, включая v4, v5, v8 и v9, остаются импортируемыми. Импорт преобразует выбранные тепловые данные при различии единицы файла и текущей единицы Home Assistant. Старые файлы без единицы считаются Celsius: все опубликованные версии, создававшие их, хранили Celsius. Экспорт доступен, пока расписание остановлено для обновления единицы, поэтому можно сохранить контрольную копию до сброса и импортировать после.

Если устройство было недоступно во время переноса или импорта, Velair проверяет его пределы и фактический температурный шаг. Допустимый `target_temp_step`, опубликованный Home Assistant, имеет приоритет над последним сообщённым шагом, затем над ручным резервным значением зоны. Панель предупреждает о несовместимой сохранённой цели, позволяя исправить её до использования расписания.

Полное поведение обновления, переноса, резервного копирования и восстановления описано в [Единицах температуры и переносе данных](temperature-units.ru.md).

Когда помощь по датчику комнаты включена и температурный блок управляется, Room Assist показывает компактную текущую температурную шкалу. Для одной цели отмечаются цель расписания, комнатный датчик, цель устройства и показание термостата. Нейтральная полосатая область обозначает нижнюю и верхнюю границы зоны нечувствительности. С фиксированным `heat` или `cool` статус также показывает направление к нижней или верхней границе; с автоматическими режимами одной температуры полоса остаётся нейтральным допуском. Для нативного диапазона она идёт от нижней цели минус зона нечувствительности до верхней плюс зона нечувствительности; отдельные скобки показывают полные запланированные и применённые диапазоны, а соединение центров показывает знаковый сдвиг всего диапазона. Комнатный датчик и показания устройства остаются отдельными маркерами. Полная переведённая легенда центрируется по представленному диапазону нечувствительности, даже если она уже текста; нулевая зона нечувствительности убирает поверхность и обозначается явно. Скрытие `show_room_assist_deadband` скрывает вместе настройку, полосу и легенду. Значения выводятся из состояния Home Assistant и работы Velair; новая история не сохраняется. Если управляемого температурного блока нет, вкладка показывает ожидание вместо фиктивных значений. Если датчик выбран, но помощь выключена, вкладка показывает, что он сохранён, но не используется для управления.

Помощь по датчику комнаты работает по событиям. Velair не опрашивает температуру. Во время активной помощи он слушает только настроенный комнатный датчик и климатическую сущность, объединяет изменения по задержке обновления устройства, выравнивает временные цели по фактическому опубликованному, последнему сообщённому или настроенному шагу, игнорирует движения меньше шага и восстанавливает реальную цель расписания при паузе планировщика или зоны, начале форсированного режима, выключении блока, непригодном датчике или отключении функции. Очистка рабочего состояния очищает и фазу гистерезиса фиксированного режима. Если адаптивная подготовка уже начала будущий блок раньше, Room Assist следует его цели до запланированного времени комфорта, не возвращаясь к предыдущему блоку.

Когда подготовка устройства отключена, Velair не регистрирует её температурные обработчики, не назначает пересчёты, не начинает обучение и не сохраняет новые наблюдения. Ранее изученные образцы сохраняются и могут использоваться при повторном включении.

Velair также хранит компактную локальную историю обучающих попыток подготовки. При применении ранней комфортной цели он открывает рабочую сессию обучения, затем сохраняет компактное наблюдение при достижении температурного порога или наступлении времени комфорта. Сессии, прерванные форсированным режимом, паузой, остановкой планировщика или изменением расписания, отбрасываются.

Вкладка подготовки показывает локальное состояние обучения каждого устройства. Обогрев и охлаждение учитываются отдельно; неподдерживаемое сущностью направление показано недоступным. При достаточном числе полных наблюдений поддерживаемого направления Velair может использовать сходную локальную историю вместо начальной модели.

Каждое поддерживаемое направление имеет компактную карточку состояния: готово ли обучение, какой источник модели активен и сколько полных, частичных и недопустимых образцов.

Вкладка также позволяет сбросить обучение каждого поддерживаемого направления. Это независимо калибрует обогрев или охлаждение с нуля, сохраняя расписания, настройки подготовки и историю другого направления.

Восстановление настроек устройства отделено от сброса обучения. Оно восстанавливает только параметры адаптивной подготовки, сохраняя текущее состояние включения, настройки комнатного датчика и все образцы обогрева и охлаждения.

Частичные наблюдения не превращаются в вымышленные сроки достижения цели. Они задают нижнюю границу: Velair знает, что потребовалось больше времени, чем испробованное окно раннего начала. Если достаточные более поздние полные наблюдения подтверждают успех меньшего опережения, старые частичные перестают увеличивать прогноз. Это сохраняет осторожность обучения без постоянного закрепления больших опережений.

Velair хранит отдельные компактные истории обогрева и охлаждения, чтобы сезонное использование одного направления не вытесняло обучение другого.

Все настройки и расчёты подготовки выполняются локально внутри Home Assistant. Velair не отправляет историю климатических устройств или данные расписаний внешним службам.

Подробности для разработчиков о локальных состояниях обучения, ответах API и правилах прогнозирования описаны в [Внутреннем устройстве адаптивной подготовки](../developer/adaptive-preconditioning.md).

<a id="environmental-comfort"></a>
## Комфорт в помещении

Вкладка Комфорт перечисляет управляемые устройства в порядке Настроек. Для каждого она отслеживает комнатную температуру, влажность и CO2. Также возможны дополнительные показания точки росы, абсолютной влажности и Humidex, рассчитанные локально по фактической температуре и влажности либо предоставленные существующим датчиком Home Assistant.

Комфорт только наблюдает. Он не меняет блоки расписания, цели устройств, режимы вентилятора, предустановки или паузы. Вместо этого Velair описывает комнату понятными состояниями вроде `Холодно и влажно`, отдельно оценивает воздух по CO2, сообщает полноту показаний и отправляет события автоматизаций при изменении оценки.

Температура может поступать от отдельного датчика комфорта, настроенного комнатного датчика Room Assist или собственного `current_temperature` климатической сущности. Влажность может поступать от выбранного датчика либо `current_humidity` сущности, когда доступна. CO2 оценивается только при выбранном датчике CO2.

Простая модель комфорта по умолчанию использует один прямоугольный диапазон температуры и влажности. Модель с подбором психрометрического диапазона превращает опорный диапазон влажности в средней точке в кривую, зависящую от температуры. Пользовательская температурно-зависимая модель позволяет задать разные пределы влажности на холодном и тёплом концах диапазона; Velair интерполирует фактический диапазон и показывает наклонную целевую область, не утверждая универсальность комфорта. Существующие зоны остаются на простой модели до явной смены.

Эти дополнительные показания по умолчанию отключены и только информативны: они не меняют классификацию комфорта или климатическое поведение. Если Комфорт отключён для устройства, Velair не регистрирует его обработчики датчиков комфорта. При включении он слушает только соответствующие выбранные датчики и климатическую сущность. Постоянного опроса нет.

Комфорт также может сравнивать комнату с явно выбранным наружным температурным датчиком и необязательным датчиком влажности. Блок **Indoor vs outdoor** (внутри и снаружи) показывает разницу температур, внутреннюю и наружную абсолютную влажность и относительную влажность, которую наружный воздух имел бы при внутренней температуре. Когда бэкенд определяет полезное направление или конфликт, Velair показывает одно осторожное сообщение о проветривании; сравнение никогда не считается командой. Настройки находятся в свёрнутой области настройки комфорта; отключение сравнения сохраняет выбранные ID датчиков. Элементы **Ventilation guidance** (рекомендации по проветриванию) для каждого устройства позволяют требовать большие или меньшие различия температуры, прогнозируемой влажности и содержания влаги до показа сообщения; исходные осторожные допуски остаются по умолчанию.

Подробные примеры настройки, обогрева, охлаждения, CO2, автоматизаций и конфиденциальности описаны в [Комфорте в помещении](comfort.ru.md).

<a id="templates"></a>
## Шаблоны

Шаблоны — повторно используемые дневные наборы блоков. Их настройки могут быть ручными или использовать общие пресеты Velair. Вкладка Шаблоны также содержит библиотеку климатических пресетов; пресет Velair позволяет совместно использовать климатические настройки, сохраняя независимое время начала блоков.

Вкладка Шаблоны позволяет:

- создать шаблон;
- переименовать шаблон;
- редактировать блоки шаблона;
- применять его к выбранным устройствам и дням недели;
- удалять шаблоны без связанных дней.

В Расписаниях выберите шаблон как источник дня, чтобы связать его время или полную конфигурацию. Копирование шаблона остаётся отдельной операцией.

Вкладка Расписания также позволяет сохранить текущий день как новый шаблон.

При копировании или связывании шаблона с устройством Velair проверяет режимы HVAC, типы целей, температурные пределы и ограничения поставщика. Цели вне диапазона и несовместимые режимы отклоняются. Ручные настройки подстраиваются к поддерживаемым шагам температуры; значения общих пресетов адаптируются к каждому назначению без изменения библиотеки. Неподдерживаемые необязательные настройки удаляются, если блок сохраняет допустимое действие.

Копирование блоков создаёт независимое время, но сохраняет действующие ссылки пресетов. Связи **Только время** синхронизируют время, оставляя климатические назначения независимыми. Связи **Время и настройки** синхронизируют полный шаблон с доступными только для чтения элементами назначения. Изменения шаблона проверяют каждый связанный день, включая неактивные профили. Редактирование сохраняет место шаблона в библиотеке.

Все правила см. в [Пресетах блоков и связанных шаблонах](linked-schedules.ru.md), а готовые конфигурации, резервные назначения новых блоков, преобразования связей, счётчики использования и устранение проблем — в [Практических примерах](linked-schedule-examples.ru.md).

Шаблоны могут включать все необязательные климатические настройки, доступные среди управляемых устройств. Поэтому один шаблон полезен для смешанных установок. При применении к конкретному устройству Velair сохраняет только поддерживаемые им параметры. Например, шаблон может содержать `fan_mode: quiet` для кондиционера, но поле автоматически удаляется при применении к термоголовке без режимов вентилятора.

<a id="climate-profiles"></a>
## Климатические профили

Климатические профили переключают несколько зон между согласованными недельными планами без перезаписи расписаний по умолчанию. Профиль может дать зоне альтернативное недельное расписание, приостановить её, приостановить и выключить или оставить на расписании по умолчанию. Пропущенные в профиле зоны продолжают свои обычные расписания.

Режим может активировать несколько профилей одновременно, если их зоны не пересекаются. Прямая активация заменяет активный набор одним профилем и выбирает **Ручной**. Зоны, охваченные прежним набором, но не этим профилем, возвращаются к расписаниям по умолчанию. Активация применяет блоки, действующие сейчас, включая начавшиеся ранее в другой день, и отменяет форсированные режимы затронутых зон. Глобальные и зональные паузы сохраняют приоритет.

В боковой панели **Расписания** — полное рабочее место планирования. Выберите **Расписания по умолчанию** для редактирования обычного недельного плана или **Расписания Профилей** для создания профиля и поочерёдной настройки каждого термостата через **Расписание по умолчанию**, **Расписание профиля** или **Приостановить расписание**. Оба источника дают ту же шкалу, параметры блоков, шаблоны и клонирование, но намеренно сохраняются по-разному: день по умолчанию сохраняется напрямую, а метаданные профиля и поведение термостатов — атомарно как единый профиль. Профиль по-прежнему можно активировать из его строки. Отдельная вкладка **Режимы** объединяет профили в повторно используемые конфигурации и не дублирует редактор расписаний. Пока Velair обрабатывает затронутые зоны, глобальная полоса операции показывает текущую зону, обработанное число и итоговый успех или частичную ошибку во всех вкладках. В Lovelace она видна только в карточке активной конфигурации, где выполняются активации режимов и профилей. Обработано означает, что Home Assistant и Velair закончили обработку зоны, включая случаи, когда пауза или переопределение делают климатическую команду ненужной. Это не означает достижения целевой температуры комнатой. Успешные результаты исчезают автоматически после краткого подтверждения. Частичные и неуспешные остаются до закрытия. Автоматизации Home Assistant могут активировать один профиль через `velair.activate_profile` или выбрать настраиваемое значение нативной сущности `select.velair_mode`.

Подробности настройки, автоматизаций, перезапуска, взаимодействий и переноса см. в [Климатических профилях](climate-profiles.ru.md).

<a id="external-schedule-execution"></a>
## Внешнее выполнение расписания

Обычно Velair хранит недельный план зоны и выполняет его через сущность `climate.*` Home Assistant. Если **Настройки → Внешние системы** обнаруживают совместимый контроллер, подходящая зона может передать выполнение ему. Velair публикует полное действующее недельное расписание, выбранное расписанием по умолчанию, профилем или режимом. Сначала зона должна иметь сохранённое действующее расписание хотя бы с одним температурным блоком; иначе Velair сохраняет локальное выполнение и объясняет требование в Настройках.

Внешняя зона ограничена расписанием. Velair не отправляет прямые климатические действия для форсированного режима, паузы/возобновления, ручной настройки, Room Assist или адаптивной подготовки. Поведение профиля **Приостановить расписание** недоступно; **Расписание по умолчанию** и **Расписание профиля** выбирают публикуемую неделю. Ограничения контроллера показываются один раз на используемую систему в Настройках и применяются при редактировании совместимых расписаний по умолчанию и профилей. Когда контроллер требует неявную точку непрерывности в полночь, редактор включает её в видимое число дневных точек переключения.

Обзор сообщает только о публикации, принятой публикации или ошибке после попытки в текущем запуске Home Assistant. Принятая публикация означает, что внешняя интеграция приняла вызов службы, а не подтверждает применение расписания физическим контроллером. Зона сохраняет обычную активность расписания и следующее событие, а компактный индикатор **Внешний** показывает контроллер и состояние публикации. Velair не опрашивает, не считывает результат обратно и не повторяет попытку автоматически. Поддерживаемые системы, ограничения, передачу управления и текущую проверку см. во [Внешнем выполнении расписания](external-systems.ru.md).

<a id="clone-schedules"></a>
## Клонировать расписания

Под редактором Velair может клонировать текущий день:

- в другие дни недели того же устройства;
- в тот же день недели других управляемых устройств.

При клонировании дней **Пн–Пт**, **Выходные**, **Все дни** и **Очистить выбор** быстро выбирают назначения, сохраняя возможность выбирать отдельные дни. Эти действия меняют только выбор назначений; **Копировать** остаётся явным действием, а исходный день никогда не включается.

Клонирование сначала сохраняет ожидающие правки, когда нужно. Копируется исходная конфигурация, включая шаблон, тип связи, назначения только времени и ссылки пресетов. Клонирование независимого дня удаляет связь назначения для этого дня; другие дни сохраняют связи. Несовместимые назначения отклоняют клонирование без изменения любого выбранного назначения. Используйте **Отвязать** после клонирования, если новый день должен перестать следовать шаблону.

<a id="pause-stop-and-resume"></a>
## Пауза, остановка и возобновление

Velair имеет глобальные элементы планировщика:

- **Пауза** приостанавливает автоматическое выполнение на длительность в минутах.
- **Остановить** приостанавливает выполнение бессрочно.
- **Возобновить** возвращает планировщик к автоматической работе.

Во время временной паузы Обзор показывает оставшееся время и прогресс.

Длительность паузы и форсированного режима вводится в минутах. Интерфейс служб Home Assistant допускает до 10 080 минут, то есть семь дней.

Velair также поддерживает паузы по зонам через службы и автоматизации. Зональная пауза затрагивает только одну управляемую климатическую сущность; остальные продолжают расписания. При возобновлении зоны Velair применяет текущее расписание только при наличии действующего блока для устройства в этот момент; иначе не меняет устройство.

<a id="boost"></a>
## Форсированный режим

Форсированный режим действует для одной климатической зоны. Он временно заменяет расписание одной сущности, оставляя другие зоны в обычной работе.

При начале форсированного режима Velair сохраняет текущее восстанавливаемое состояние устройства зоны, включая режим HVAC и одну цель или полный диапазон, когда Home Assistant их предоставляет. Снимок используется только для решения о завершении форсированного режима.

Форсированный режим доступен через службы, скрипты, автоматизации и элементы панелей Home Assistant. Это сохраняет направленность основного редактора на расписание и позволяет сложные автоматизации, например:

- включать форсированный режим комнаты кнопкой;
- включать его после движения;
- запускать через голосового помощника;
- запускать с предпочитаемым режимом HVAC.

При истечении форсированного режима Velair обрабатывает зону в таком порядке:

1. Если есть активный блок с явным режимом HVAC, применяется его запланированная цель.
2. Если активный блок выключает устройство, Velair выключает его.
3. Если активного блока нет, восстанавливается состояние, сохранённое до форсированного режима.
4. Если активный блок использует `Сохранить режим`, Velair также восстанавливает прежнее состояние: `Сохранить режим` не задаёт новый режим HVAC после временного переопределения.

Таким образом, форсированный режим не должен заставлять Velair придумывать новую цель обогрева или охлаждения, если текущее расписание её явно не определяет.

<a id="startup-behavior"></a>
## Поведение при запуске

По умолчанию Velair восстанавливает сохранённое состояние планировщика после запуска Home Assistant, но не принуждает устройства к цели расписания.

В Настройках можно включить **Применять активное расписание после запуска**. Тогда Velair применяет текущий действующий блок к управляемым устройствам после запуска Home Assistant, если планировщик в автоматическом режиме. Блок, начавшийся в предыдущий день, остаётся активным до следующего недельного блока. Активные форсированные режимы учитываются.

<a id="automation-blueprints"></a>
## Шаблоны автоматизаций

Velair предоставляет необязательные шаблоны автоматизаций Home Assistant через документацию:

- переключение выбранных действий Дома/Вне дома по одной объединённой сущности присутствия;
- пауза одного или нескольких устройств, пока открыта любая выбранная дверь или окно;
- выбор сезонных режимов или других действий один раз после подтверждения нового сезонного диапазона, с немедленными уведомлениями о недопустимых показаниях.

Они используют события состояния Home Assistant и настраиваемые задержки, а не опрос. Шаблон присутствия может сообщить о постоянно недоступной объединённой группе, шаблонном датчике или помощнике, не выполняя действия Дома/Вне дома. Шаблон окон идентифицирует создаваемую паузу, поэтому закрытие окна не удалит ручную паузу или паузу другой автоматизации. Если контакт остаётся неизвестным или недоступным, Home Assistant показывает одно отложенное диагностическое уведомление для набора термостатов и автоматически убирает его после восстановления; затронутый контакт продолжает препятствовать возобновлению. Настройку, примеры, запуск и правило одной автоматизации на зону для контактов см. в [Шаблонах автоматизаций](blueprints.ru.md).

[Сезонный шаблон](blueprints/seasonal-climate-selection.ru.md) по умолчанию подтверждает новый сезонный диапазон в течение 30 минут. Изменения внутри этого диапазона сохраняют исходный срок; действия выполняются один раз при каждом входе в диапазон. При запуске проверяется только диагностика. Выбирайте режимы Velair в обычном редакторе действий Home Assistant. Настройте настоящий режим паузы с выключением, если мягкая погода должна остановить климатическое оборудование; пустые действия сохраняют текущую работу.

<a id="portability"></a>
## Перенос данных

Вкладка Настройки экспортирует и импортирует JSON-файл с номером версии.

Файл может содержать:

- расписания термостатов;
- шаблоны;
- общие пресеты блоков;
- настройки панели;
- обучение адаптивной подготовки;
- определения климатических профилей;
- определения режимов.

Текущая модель 19 сохраняет оба типа связи шаблонов, ссылки пресетов и связи ведущих термостатов предварительной подготовки. Подтверждённые опорные данные выполнения ведущего устройства остаются локальными и не экспортируются. Экспорт расписаний или профилей включает необходимые шаблоны и пресеты как дополнительные выбранные разделы. Импорт проверяет объединённую конфигурацию, включая существующих потребителей заменяемых общих ресурсов. Пресеты объединяются по стабильному ключу: совпадающие заменяются, а локальные пресеты, которых нет в файле, остаются. Прежние резервные копии можно импортировать; старые версии Velair не импортируют файлы модели 19. См. [пример резервного копирования](linked-schedule-examples.ru.md#back-up-the-whole-setup).

При импорте Velair позволяет выбрать разделы для перезаписи. Импорт заменяет выбранные данные; сначала экспортируйте, если нужна точка восстановления. Определения профилей и режимов переносимы, а активный выбор — нет. Velair сохраняет активные ID профилей, которые ещё существуют, и возвращается к расписаниям по умолчанию только когда не осталось ни одного.

Каждый новый экспорт записывает единицу температуры. При импорте файла с другой системой единиц Velair преобразует выбранные тепловые значения в текущую единицу Home Assistant. Значения доступного устройства выравниваются по фактическому целевому шагу; значения, не привязанные к устройству, используют безопасную точность без общего шага устройства. Ручное резервное значение зоны переносится, а последний наблюдавшийся шаг локальной сущности намеренно не экспортируется. Старые экспорты без записанной единицы отмечаются на экране импорта и считаются Celsius.

Обучение адаптивной подготовки сопоставляется по точному ID климатической сущности Home Assistant. Данные неуправляемых сейчас устройств показываются до импорта и пропускаются. Для совпавших устройств импорт заменяет текущую калибровку. Обучение локальных устройств, отсутствующих в файле, не меняется.

Параметры подготовки уже включены в **Расписания термостатов**. Отдельный раздел **Обучение предварительного прогрева** содержит накопленную локальную историю калибровки.

<a id="maintenance"></a>
## Обслуживание

Вкладка Настройки показывает технические версии:

- сборка интерфейса;
- версия модели переносимого экспорта;
- версия хранилища/модели;
- версия интеграции.

Также есть сброс. Он удаляет все сохранённые данные расписаний Velair, включая расписания, шаблоны, предпочтения панели, активные форсированные режимы и паузы, политики внешних изменений устройств и активные ручные настройки, параметры комфорта и Room Assist, настройки и обучение адаптивной подготовки и поведение при запуске. Затем создаются новые значения по умолчанию с учётом единиц для текущих управляемых устройств. Отдельный выбор категорий Диагностики и текущий журнал не входят в сброс данных расписаний. Velair запрашивает подтверждение перед выполнением.

<a id="services"></a>
## Службы

Velair предоставляет службы Home Assistant для автоматизаций и скриптов:

- `velair.set_temperature`
- `velair.set_hvac_mode`
- `velair.apply_schedule`
- `velair.boost`
- `velair.cancel_boost`
- `velair.activate_profile`
- `velair.deactivate_profile`
- `velair.enable_room_sensor_assist`
- `velair.disable_room_sensor_assist`
- `velair.pause`
- `velair.pause_zone`
- `velair.resume`
- `velair.resume_zone`
- `velair.set_external_change_policy`
- `velair.enter_manual_adjustment`
- `velair.resume_automatic_control`
- `velair.set_daily_schedule`
- `velair.copy_day_schedule`
- `velair.clear_schedule`
- `velair.update_block_preset`

Службы с целевой сущностью работают только с устройствами, выбранными при настройке. Передача неуправляемой сущности приводит к отклонению вызова до любых изменений.

<a id="velairupdate_block_preset"></a>
### `velair.update_block_preset`

Обновите сохранённый общий пресет по его стабильному `preset_key`. Частичные обновления сохраняют пропущенные поля; явная замена может изменить действие. Изменения затрагивают все ссылки и используют обычную проверку, приоритет переопределений и пересчёт подготовки. Поля и примеры наружной температуры, диапазона, параметров устройств и выключения/восстановления см. в [Автоматизациях пресетов](preset-automations.ru.md). Служба меняет общее определение; она не выбирает другой пресет для блока.

<a id="velairactivate_profile"></a>
### `velair.activate_profile`

Активируйте один сохранённый климатический профиль и немедленно примените фактическое текущее поведение. Это заменяет весь активный набор профилей; зоны, не охваченные выбранным профилем, возвращаются к расписаниям по умолчанию. Используйте показанный Velair стабильный ID профиля, а не редактируемое имя. Прямая активация устанавливает селектор режима в `Manual`. Пропуск `profile_id` по-прежнему возвращает обычные расписания для совместимости; новые автоматизации должны явно использовать `velair.deactivate_profile`.

```yaml
action: velair.activate_profile
data:
  profile_id: vacation
```

<a id="velairdeactivate_profile"></a>
### `velair.deactivate_profile`

Деактивируйте все активные профили и немедленно верните каждую зону к расписанию по умолчанию.

```yaml
action: velair.deactivate_profile
```

<a id="velairset_temperature"></a>
### `velair.set_temperature`

Задайте одному управляемому устройству одну температуру или диапазон нижней и верхней целей. `hvac_mode` необязателен.

Это удобная служба в области Velair, а не замена `climate.set_temperature` Home Assistant. Отличия:

- принимает только климатические сущности Velair;
- проверяет цель по известным Velair возможностям и температурным пределам;
- использует резервные правила выбора режима HVAC Velair, когда режим указан или устройство нужно включить.

Для общего климатического управления используйте нативные службы Home Assistant. Используйте `velair.set_temperature`, когда автоматизация должна затрагивать только управляемые Velair устройства.

Также можно передать необязательные поля `fan_mode`, `preset_mode`, `swing_mode`, `swing_horizontal_mode` и `humidity`. Velair применяет только поддерживаемые целевым устройством поля.

```yaml
action: velair.set_temperature
data:
  entity_id: climate.living_room
  temperature: 21
  hvac_mode: heat
  fan_mode: quiet
```

Для диапазона пропустите `temperature` и передайте обе границы:

```yaml
action: velair.set_temperature
data:
  entity_id: climate.living_room
  target_temp_low: 20
  target_temp_high: 24
  hvac_mode: heat_cool
```

`temperature` и поля диапазона взаимоисключающие. Обе границы диапазона нужны вместе.

<a id="velairset_hvac_mode"></a>
### `velair.set_hvac_mode`

Установите один объявленный режим HVAC, кроме выключения, без отправки целевой температуры. Velair принимает только управляемые устройства с локальным выполнением, проверяет режим по сущности и записывает команду как своё действие, чтобы не принять её за внешнее изменение.

```yaml
action: velair.set_hvac_mode
data:
  entity_id: climate.living_room
  hvac_mode: auto
```

Используйте службу, когда автоматизации Velair нужно менять только режим HVAC. Velair не включает одну цель или диапазон в вызов; интеграция или устройство всё равно могут внутренне изменить своё состояние при смене режима. Успешная доставка отключает активный Room Assist, поскольку Velair больше не управляет температурной целью этой команды. Ошибка доставки оставляет Room Assist без изменений и не отправляет событие успешного применения цели.

Для общего управления вне Velair используйте нативную `climate.set_hvac_mode` Home Assistant. Режим `off` намеренно отклоняется; для этого отдельного намерения используйте подходящую паузу, расписание или климатическое действие Velair.

<a id="velairapply_schedule"></a>
### `velair.apply_schedule`

Немедленно примените текущий активный блок. Если `entity_id` отсутствует, Velair применяет активный блок ко всем управляемым устройствам.

```yaml
action: velair.apply_schedule
data:
  entity_id: climate.living_room
```

<a id="velairboost"></a>
### `velair.boost`

Временно переопределите управление одной климатической сущностью. При истечении Velair применяет активную явную цель расписания, если есть, либо восстанавливает сохранённое до форсированного режима состояние, если явной цели для применения нет.

```yaml
action: velair.boost
data:
  entity_id: climate.living_room
  temperature: 22
  duration_minutes: 45
  hvac_mode: heat
  fan_mode: high
```

Velair сохраняет восстанавливаемое состояние до применения форсированного режима. Запуск отклоняется, если устройство недоступно и состояние нельзя безопасно сохранить.

Форсированный режим с диапазоном использует `target_temp_low` и `target_temp_high` вместо `temperature` по тем же правилам, что `velair.set_temperature`.

<a id="velaircancel_boost"></a>
### `velair.cancel_boost`

Досрочно отмените активный форсированный режим. Поведение всегда совпадает с обычным истечением: применяется активная явная цель расписания, если есть; иначе, включая блок `Сохранить режим`, восстанавливаются сохранённые до форсированного режима режим HVAC и цель. Вызов без активного форсированного режима ничего не меняет.

```yaml
action: velair.cancel_boost
data:
  entity_id: climate.living_room
```

<a id="velairenable_room_sensor_assist"></a>
### `velair.enable_room_sensor_assist`

Включите помощь по датчику комнаты для одного управляемого устройства. Для него уже должен быть настроен комнатный температурный датчик на вкладке Room Assist.

```yaml
action: velair.enable_room_sensor_assist
data:
  entity_id: climate.living_room
```

<a id="velairdisable_room_sensor_assist"></a>
### `velair.disable_room_sensor_assist`

Отключите помощь по датчику комнаты для одного управляемого устройства. Если Velair применял скорректированную цель, он восстанавливает текущую цель расписания.

```yaml
action: velair.disable_room_sensor_assist
data:
  entity_id: climate.living_room
```

<a id="velairpause"></a>
### `velair.pause`

Приостановите автоматическое выполнение расписания. Пропустите `duration_minutes`, чтобы остановить его бессрочно.

```yaml
action: velair.pause
data:
  duration_minutes: 60
```

<a id="velairresume"></a>
### `velair.resume`

Возобновите автоматическое выполнение и примените текущее расписание.

```yaml
action: velair.resume
```

<a id="velairpause_zone"></a>
### `velair.pause_zone`

Приостановить автоматическое выполнение расписания одной управляемой климатической сущности, пока остальная часть Velair продолжает работу. Для бессрочной паузы не указывайте ни `duration_minutes`, ни `until_next_block`.

Установите `until_next_block: true`, чтобы завершить эту паузу в начале следующего блока действующего расписания зоны. Используется номинальное время блока, а не раннее начало адаптивной подготовки. Время окончания фиксируется при вызове службы и сохраняется после перезапусков; последующие правки расписания его не сдвигают. Нельзя сочетать с `duration_minutes`; если будущего блока нет, вызов завершается ошибкой без изменения зоны. Другие причины паузы продолжают удерживать зону на паузе, пока также не завершатся.

```yaml
action: velair.pause_zone
data:
  entity_id: climate.guest_room
  pause_id: external_control
  action: none
  until_next_block: true
```

Необязательное поле `action` может быть:

- `none`: оставить устройство точно как есть и только запретить Velair менять его автоматически;
- `turn_off`: немедленно выключить устройство и оставить на паузе.

Автоматизации также могут передать необязательный `pause_id` из 1–128 букв, цифр, точек, подчёркиваний, двоеточий или дефисов, начинающийся с буквы или цифры. Идентифицированная пауза добавляет причину без замены причин с другими ID. Повторное использование ID обновляет только эту причину; точный повтор ничего не меняет. Вызовы без `pause_id` сохраняют ручной приоритет и заменяют все причины одной ручной паузой.

```yaml
action: velair.pause_zone
data:
  entity_id: climate.guest_room
  duration_minutes: 120
  action: turn_off
  pause_id: window_guard
```

<a id="velairresume_zone"></a>
### `velair.resume_zone`

Возобновите автоматическое выполнение одной управляемой сущности. По умолчанию Velair применяет текущий активный блок для неё, если есть. Если в этот момент блока нет, устройство не меняется.

При переданном `pause_id` Velair удаляет только эту причину. Другие причины сохраняют паузу, а расписание применяется после окончания последней. Используйте `resume_all: true`, чтобы явно убрать все причины. Пропуск обоих полей сохраняет прежнее поведение полного возобновления. Поля нельзя сочетать; `resume_all: false` без ID отклоняется.

Причины истекают независимо. Если любая оставшаяся использует `turn_off`, фактическое действие паузы остаётся выключением. Форсированные режимы отклоняются, пока зона на паузе.

```yaml
action: velair.resume_zone
data:
  entity_id: climate.guest_room
  apply_current_schedule: true
  pause_id: window_guard
```

<a id="velairset_daily_schedule"></a>
### `velair.set_daily_schedule`

Замените расписание одного дня недели для одного управляемого устройства.

```yaml
action: velair.set_daily_schedule
data:
  entity_id: climate.living_room
  weekday: monday
  blocks:
    - start: "06:30"
      action: set_temperature
      temperature: 21
      hvac_mode: heat
      fan_mode: quiet
    - start: "09:00"
      action: turn_off
    - start: "18:00"
      action: set_temperature
      temperature: 20
      hvac_mode: heat
```

Блоки могут содержать необязательные `fan_mode`, `preset_mode`, `swing_mode`, `swing_horizontal_mode` и `humidity`. Неподдерживаемые значения удаляются для целевого устройства перед сохранением или применением расписания.

Используйте `action: set_climate_options` с одним или несколькими этими полями и без температуры или `hvac_mode`, чтобы вызвать только соответствующие службы Home Assistant. Например:

```yaml
action: velair.set_daily_schedule
data:
  entity_id: climate.living_room
  weekday: monday
  blocks:
    - start: "06:30"
      action: set_climate_options
      preset_mode: comfort
    - start: "22:00"
      action: set_climate_options
      preset_mode: eco
      fan_mode: quiet
```

<a id="velaircopy_day_schedule"></a>
### `velair.copy_day_schedule`

Скопируйте сохранённый день расписания по умолчанию, включая связь шаблона и ссылки пресетов, в выбранные дни недели. Пропустите `target_entity_ids`, чтобы копировать в исходном устройстве, либо передайте список для других управляемых устройств. Все выбранные сочетания устройства/дня проверяются и сохраняются одной транзакцией.

```yaml
action: velair.copy_day_schedule
data:
  entity_id: climate.living_room
  source_weekday: monday
  target_weekdays:
    - tuesday
    - wednesday
    - thursday
```

Для копирования той же настройки понедельника в другие термостаты:

```yaml
action: velair.copy_day_schedule
data:
  entity_id: climate.living_room
  source_weekday: monday
  target_weekdays:
    - monday
  target_entity_ids:
    - climate.study
    - climate.bedroom
```

Служба копирует последнее сохранённое исходное расписание под блокировкой конфигурации. Необязательное `expected_revision` отклоняет операцию при изменившейся конфигурации; панель автоматически передаёт текущую ревизию. Профили редактируются и сохраняются отдельным процессом, который обрабатывает профиль целиком. Копирование независимого сохранённого дня удаляет связи шаблонов выбранных дней назначения; другие дни сохраняются.

<a id="velairclear_schedule"></a>
### `velair.clear_schedule`

Очистите расписание одного дня недели. Пропустите `weekday`, чтобы очистить все дни этого управляемого устройства.

```yaml
action: velair.clear_schedule
data:
  entity_id: climate.living_room
  weekday: sunday
```

<a id="automation-events"></a>
## События автоматизаций

Velair также отправляет события Home Assistant для триггеров автоматизаций. События кратковременны: они не сохраняются как конфигурация и не заменяют диагностические сущности.

Все рабочие события используют один тип события Home Assistant:

```text
velair_event
```

Поле `event` в данных обозначает изменения набора профилей, режима планировщика, применённые цели, планы и наблюдения адаптивной подготовки, изменения комфорта, состояния и целей Room Assist, форсированные режимы и паузы зон.

Точные правила отправки, устранение повторов, доступные поля и полный пример данных каждого типа см. в [Событиях автоматизаций](automation-events.ru.md).
