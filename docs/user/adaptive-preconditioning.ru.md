Адаптивная подготовка позволяет Velair начать отопление или охлаждение до запланированного блока, чтобы к его началу температура помещения была ближе к цели.

Например, блок расписания на `07:00` с `21 °C` означает «приблизиться к `21 °C` к `07:00`», а не «начать менять температуру на `21 °C` в `07:00`».

Подготовка выполняется локально внутри Home Assistant. Velair хранит настройки и обучающие наблюдения в хранилище Home Assistant и никогда не отправляет историю температур, наблюдения или калибровочные данные внешнему контроллеру. Зоны с внешним выполнением расписания не используют адаптивную подготовку; публикуется только их действующее недельное расписание.

<a id="setup"></a>
## Настройка

Вкладка **Предварительный прогрев** предлагает два инструмента в селекторе подразделов. По умолчанию открывается адаптивная подготовка; выберите запланированное возвращение, чтобы настроить присутствие, еженедельные возвращения и управлять текущим отсутствием. Прямые пути панели: `/velair/preconditioning/preconditioning` и `/velair/preconditioning/planned-return`. См. [Запланированное возвращение](planned-return.ru.md). Несмотря на название вкладки, подготовка поддерживает и отопление, и охлаждение.

1. Откройте вкладку **Предварительный прогрев**.
2. Разверните нужное устройство.
3. Включите подготовку.
4. Оставьте настройки модели по умолчанию, если нет конкретной причины их менять.
5. При желании выберите датчик наружной температуры.

Подготовка настраивается отдельно для каждого устройства. Обучение отоплению и охлаждению ведётся раздельно: наблюдения охлаждения не заменяют отопление и наоборот.

Поддерживаются собственные диапазоны `heat_cool`. Если температура комнаты ниже нижней цели больше, чем **Минимальная разница температур**, Velair строит прогноз по нижней границе и раньше запускает полный диапазон для отопления. Если температура выше верхней цели больше этой разницы, прогноз строится по верхней границе для охлаждения. Показания внутри диапазона или зон нечувствительности около границ сохраняют обычное время расписания. Velair всегда отправляет обе границы и никогда не сводит диапазон к одной температуре.

При разворачивании устройства для каждого поддерживаемого режима появляется карточка текущего прогноза. Она использует те же данные следующего события серверной части, что обзор, поэтому паузы, форсированные режимы, неподдерживаемые режимы и блоки без подготовки обрабатываются одинаково. Если есть подходящий будущий блок, карточка показывает рассчитанное начало, целевое время, опережение, температуру и режим расписания и источник модели: начальную модель или похожую локальную историю.

Для проверки расчёта откройте **Детали расчёта** в карточке прогноза. Необязательный раздел показывает серверные значения, включая число наблюдений, оценку по завершённым наблюдениям, нижнюю границу по неполным, совмещённую оценку, округление и итоговое опережение. По умолчанию раздел скрыт, чтобы обычное представление оставалось простым.

<a id="how-it-starts"></a>
## Как определяется начало

Velair рассчитывает текущую разницу температур для следующего температурного блока расписания.

Для диапазона `heat_cool` «целевая температура» ниже означает нижнюю границу при отоплении и верхнюю при охлаждении.

Для отопления:

```text
delta = target temperature - current temperature
```

Для охлаждения:

```text
delta = current temperature - target temperature
```

Если разница меньше минимальной разницы температур, Velair сохраняет обычное время блока и не начинает заранее.

<a id="schedule-boundaries-and-other-climates"></a>

## Границы расписания и другие устройства

Ранний запуск в недельном расписании не должен достигать или пересекать непосредственно предшествующий действующий блок расписания того же устройства, включая блок `Off`. Если расчётное окно достигает или пересекает эту границу, Velair сохраняет обычное время комфорта. Например, при `Off` в `19:00` и `heat` в `20:00` расчётный запуск в `18:00` отменяется: `Off` применяется в `19:00`, а отопление начинается в `20:00`. Блок `Off` в `22:00` предыдущего вечера не препятствует запуску в `05:35` для `07:00`, если между ними нет другого блока. Правило также действует для охлаждения и собственных диапазонов `heat_cool`; оно не меняет прогнозы прибытия для запланированного возвращения.

Устройство, уже выполняющее предварительную подготовку, не задерживает блоки или ранние запуски других устройств. Если обработка действия пересекает время другого перехода, Velair определяет текущую разрешённую цель для затронутого устройства, а не повторяет устаревшие команды. Паузы, усиления, ручная настройка, отключённые зоны и внешнее выполнение расписания по-прежнему определяют, можно ли передать цель. Такое восстановление действует во время работы планировщика; настроенное поведение применения при запуске не меняется.

<a id="initial-model-example"></a>
## Пример начальной модели

Когда локальной истории недостаточно, Velair использует начальную модель:

```text
lead = Minimum start + Initial model min/degree * temperature delta
```

Условия:

- Блок расписания: `21 °C`, `heat`, целевое время `07:00`.
- Температура комнаты: `18 °C`.
- Минимальное опережение: `10 min`.
- Начальная модель: `25 min/°C` или эквивалентные `13.89 min/°F`.
- Максимальное опережение: `24 h`.

Расчёт:

```text
delta = 21 - 18 = 3 °C
lead = 10 + 25 * 3 = 85 min
start = 07:00 - 85 min = 05:35
```

Velair применяет цель расписания в `05:35`, сохраняя `07:00` как видимое время достижения комфорта.

<a id="heating-with-learned-history"></a>
## Отопление с использованием накопленной истории

После достаточного числа успешных наблюдений Velair может использовать похожую локальную историю вместо начальной модели.

Условия:

- Блок расписания: `21 °C`, `heat`, целевое время `07:00`.
- Текущая температура комнаты: `18.5 °C`.
- Текущая разница: `2.5 °C`.
- Похожие завершённые наблюдения:

```text
A: 2.0 °C in 50 min -> 25.0 min/°C
B: 2.4 °C in 72 min -> 30.0 min/°C
C: 2.8 °C in 84 min -> 30.0 min/°C
D: 2.1 °C in 63 min -> 30.0 min/°C
E: 2.6 °C in 91 min -> 35.0 min/°C
```

При **Процентиле комфорта** `80` Velair выбирает осторожное значение из похожих завершённых наблюдений. В этом примере — `35.0 min/°C`.

```text
lead = 2.5 * 35 = 87.5 min
```

Velair округляет итоговое опережение вверх до следующей поддерживаемой минуты планировщика, а не ниже рассчитанного значения.

```text
87.5 min -> 90 min
start = 07:00 - 90 min = 05:30
```

<a id="cooling-example"></a>
## Пример охлаждения

Условия:

- Блок расписания: `23 °C`, `cool`, целевое время `22:00`.
- Температура комнаты: `27 °C`.
- Минимальное опережение: `10 min`.
- Начальная модель: `25 min/°C`.
- Максимальное опережение: `24 h`.

Расчёт:

```text
delta = 27 - 23 = 4 °C
lead = 10 + 25 * 4 = 110 min
start = 22:00 - 110 min = 20:10
```

Когда накопится достаточно наблюдений охлаждения, Velair использует только историю охлаждения. Она не смешивается с отоплением, поскольку одна комната и одно устройство могут нагреваться и охлаждаться с разной скоростью.

<a id="partial-and-invalid-observations"></a>
## Неполные и недействительные наблюдения

После попыток подготовки Velair сохраняет компактные локальные наблюдения.

Завершённые наблюдения — полезные примеры, где комната вовремя достигла целевого порога.

Неполные наблюдения означают, что Velair начал раньше, но комната не достигла целевого порога к запланированному времени комфорта. Они задают нижние границы: Velair знает, что требовалось больше времени, но не придумывает время завершения.

Недействительные наблюдения сохраняются только для диагностики и не управляют моделью. Примеры: слишком маленькая разница температур, невозможная длительность, прерванные сеансы, отсутствующая температура, форсированные режимы, паузы или изменения состояния планировщика.

Если после старых неполных наблюдений накопится достаточно завершённых, подтверждающих надёжное достижение цели, старые неполные перестают увеличивать прогноз.

<a id="outdoor-temperature-sensor"></a>
## Датчик наружной температуры

Датчик наружной температуры необязателен.

Если он настроен, Velair сохраняет показания как локальные сопутствующие данные наблюдений, а позже сравнивает текущие условия с похожими прошлыми. Он не обращается к погодным службам, не требует интернета и не добавляет фиксированную поправку к начальной модели.

Если наружный датчик недоступен при сохранении наблюдения, оно сохраняется без этих сопутствующих данных.

<a id="room-assist-interaction"></a>
## Взаимодействие с Room Assist

По умолчанию адаптивная подготовка использует `current_temperature` климатической сущности.

Если для устройства включён Room Assist и выбран отдельный комнатный датчик, подготовка использует его как фактическую температуру помещения для решений и обучения. Это датчик внутри комнаты, а не датчик наружной температуры.

Это полезно для термостатических радиаторных клапанов и термостатов, чей встроенный датчик слишком близок к радиатору, выходу воздуха или другому локальному источнику тепла. Поведение на стороне управления устройством описано в [Room Assist](room-assist.ru.md).

<a id="automation-events"></a>
## События для автоматизаций

Velair использует три события `velair_event` для этого цикла:

- `preconditioning_plan_updated`: рассчитанный план появился или изменился;
- `preconditioning_plan_cancelled`: опубликованный план больше не действует;
- `preconditioning_observation_recorded`: обучающее наблюдение сохранено.

Точные правила публикации и полные примеры данных описаны в [Событиях для автоматизаций](automation-events.ru.md#preconditioning-plan-updated).

Пример триггера автоматизации:

```yaml
trigger:
  - platform: event
    event_type: velair_event
    event_data:
      event: preconditioning_plan_updated
      entity_id: climate.living_room
```

<a id="when-velair-does-nothing"></a>
## Когда Velair ничего не делает

Адаптивная подготовка не начинается заранее, если:

- она отключена для устройства;
- планировщик не в автоматическом режиме;
- зона на паузе или в форсированном режиме;
- следующий блок — `Выкл.`;
- устройство не поддерживает нужное направление отопления или охлаждения;
- разница меньше минимальной разницы температур;
- требуемая температура недоступна или нечисловая.

<a id="lovelace"></a>
## Lovelace

Представление предварительной подготовки доступно как карточка Lovelace:

```yaml
type: custom:velair-card
view: preconditioning
entities:
  - climate.living_room
```

Карточка использует ту же конфигурацию серверной части, что основная панель Velair.
