<a id="a-lovelace-card-shows-configuration-error"></a>
## Карточка Lovelace показывает ошибку конфигурации

Убедитесь, что Velair установлен и настроен до загрузки карточки на панели управления. Интеграция делает свой frontend-ресурс доступным на раннем этапе запуска Home Assistant, поэтому при обычном перезапуске карточки не должны оставаться в ожидании модуля.

Если ошибка сохраняется:

1. Проверьте, что URL ресурса панели управления — именно `/velair_frontend/velair-card.js`, а тип — **JavaScript module**.
2. Удалите дублирующиеся или старые ресурсы, например `/local/velair-card.js`.
3. Перезапустите Home Assistant после обновления интеграции.
4. Обновите страницу в браузере или перезагрузите приложение Home Assistant.

Консоль браузера или вкладка сетевых запросов покажут, завершилась ли загрузка модуля ошибкой. При сообщении о воспроизводимой проблеме приложите полный текст этой ошибки.

<a id="velair-does-not-appear-in-the-sidebar"></a>
## Velair не появляется в боковой панели

Перезапустите Home Assistant после установки или обновления интеграции. Панель в боковом меню регистрируется при настройке интеграции.

Если интеграция только что обновлена, обновите страницу браузера без использования кэша или перезагрузите приложение Home Assistant.

<a id="the-lovelace-card-shows-old-ui"></a>
## Карточка Lovelace показывает старый интерфейс

Проверьте ресурсы панели управления. Удалите старые ресурсы разработки, например:

```yaml
url: /local/velair-card.js
type: module
```

Вместо этого используйте ресурс, предоставляемый интеграцией:

```yaml
url: /velair_frontend/velair-card.js
type: module
```

Velair предоставляет этот ресурс с заголовками, запрещающими кэширование. Боковая панель использует URL с автоматически добавленной версией и изолированные внутренние элементы, поэтому старая карточка Lovelace из кэша не может заблокировать обновление панели. Обычно после обновления интеграции достаточно перезапустить Home Assistant и обновить браузер или приложение. Если backend сообщает новую версию, но интерфейс остаётся прежним, обновите страницу без кэша или очистите данные кэша сайта, прежде чем сообщать о проблеме. Пользователям не нужно добавлять идентификаторы сборок или менять URL ресурса между версиями.

<a id="a-climate-entity-is-missing"></a>
## Климатическая сущность отсутствует

Откройте параметры интеграции Velair и убедитесь, что сущность выбрана. Velair управляет только сущностями `climate.*`, указанными в конфигурации интеграции.

Если сущности больше нет в Home Assistant, Velair покажет подтверждённую проблему в разделе **Диагностика**.

<a id="a-mode-is-not-available"></a>
## Режим недоступен

Velair получает список поддерживаемых режимов HVAC от климатической сущности. Если режим не показан, сущность не сообщает о его поддержке.

При применении шаблонов или клонировании расписаний Velair отклоняет неподдерживаемые режимы с понятной ошибкой. Выберите для блока **Оставить** или режим, поддерживаемый целевым устройством.

<a id="temperature-is-adjusted-when-applying-templates"></a>
## Температура меняется при применении шаблонов

При применении шаблона Velair проверяет его итоговые климатические настройки по возможностям термостата назначения. Сначала отклоняются температуры ниже минимального или выше максимального значения термостата. Значения внутри этих пределов затем могут округляться до поддерживаемого температурного шага, в том числе вблизи границ диапазона. Эта проверка также распространяется на общие пресеты и связанные шаблоны; несовместимая общая конфигурация не позволяет сохранить затронутую операцию. Исправьте температуру или выберите совместимое устройство назначения перед повторной попыткой.

<a id="export-does-not-download-on-mobile"></a>
## Экспорт не скачивается на мобильном устройстве

Пока экспорт намеренно доступен только на компьютере, потому что мобильные приложения неодинаково обрабатывают скачивание файлов. Импорт доступен и на компьютере, и на мобильных устройствах.

<a id="scheduler-does-not-apply-after-restart"></a>
## Планировщик не применяет настройки после перезапуска

По умолчанию Velair восстанавливает состояние после запуска Home Assistant, не отправляя команды климатическим устройствам принудительно.

Если нужно применять активное расписание после перезапуска, включите в настройках **Применять активное расписание после запуска**.

<a id="reset-to-defaults"></a>
## Сброс к значениям по умолчанию

Используйте **Настройки > Обслуживание > Сбросить Velair**. Действие удаляет все сохранённые данные Velair: расписания, шаблоны, настройки панели, активные форсированные режимы и паузы, настройки Комфорта и Room Assist, настройки и данные обучения адаптивной подготовки, а также поведение при запуске. После этого создаются значения по умолчанию с учётом единицы температуры для устройств, которыми сейчас управляет Velair.

Сначала сделайте экспорт, если существующие данные могут понадобиться для восстановления.

<a id="temperature-unit-requires-attention"></a>
## Единица температуры требует внимания

Velair получает единицу температуры из Home Assistant. Если настройки сообщают, что сохранённая единица отличается от единицы Home Assistant, автоматическое выполнение расписаний и запись температурных параметров остаются остановленными. Это не позволяет применить старое задание в неверной единице.

- Если Velair предлагает преобразовать сохранённые температуры, проверьте, что все значения ещё указаны в показанной исходной единице, затем выполните преобразование один раз. Если ничего не делать, выполнение расписаний останется остановленным; Velair никогда не преобразует данные незаметно.
- Если обновление старых опубликованных данных в градусах Цельсия требует сброса, при необходимости сначала экспортируйте справочную копию, затем используйте **Сбросить Velair**, чтобы создать значения по умолчанию в текущей единице Home Assistant.
- Если сброс, преобразование или импорт были сохранены, но восстановление состояния во время работы завершилось ошибкой, перезагрузите интеграцию Velair или перезапустите Home Assistant. Velair намеренно остаётся остановленным до восстановления.

Если после восстановления доступности устройства расписание отмечено как несовместимое, проверьте целевую температуру по сообщённому диапазону и действующему шагу устройства. Когда `target_temp_step` отсутствует, задайте фактический шаг в строке настроек этого устройства. Поле показывает последний корректный шаг, который Velair запомнил, затем сохранённое ручное запасное значение или `1`, если ни того, ни другого нет. Сохранение ручного значения при отсутствии атрибута заменяет запомненный шаг. Когда Home Assistant сообщает корректный шаг, ручное значение не используется, но сохраняется.

Старые резервные копии без указания единицы принимаются как данные в градусах Цельсия. Экран импорта показывает это предположение и преобразует выбранные температурные значения, если Home Assistant сейчас использует Фаренгейт.

Полные правила выбора действий и работы с резервными копиями описаны в руководстве [Единицы температуры и преобразование данных](temperature-units.ru.md).
