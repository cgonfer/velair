Запускайте выбранные действия Home Assistant, когда одна объединённая сущность присутствия показывает, что дома кто-то есть или дом пуст. Правила для людей, гостей и особенностей вашего дома остаются в Home Assistant, а типичные переключения режимов и профилей Velair проще настроить. Уведомление с задержкой объясняет, когда состояние сущности не позволяет надёжно выбрать между присутствием и отсутствием.

<a id="when-to-use-it"></a>
## Когда использовать

Этот сценарий подходит, если в Home Assistant уже есть одна сущность, показывающая, есть ли кто-то дома. Его можно использовать для переключений «Дома», «Отсутствие» и других подобных действий, которые нужно отложить и перед выполнением ещё раз проверить состояние.

<a id="requirements"></a>
## Требования

- Версия сценария 1.0.0 и Home Assistant 2024.6.0 или новее.
- Одна сущность `binary_sensor` или `input_boolean` со значениями `on`/`off` либо группа людей со значениями `home`/`not_home`.
- Velair нужен только в том случае, если настроенные действия используют его режимы, профили, сущности или службы. В остальных случаях сценарий может выполнять стандартные действия Home Assistant без Velair.

Сначала настройте правила для людей, гостей, зон и присутствия в Home Assistant, затем выберите здесь итоговую сущность. Группа людей может показывать, находится ли хотя бы один отслеживаемый человек в состоянии `home`, а шаблонный бинарный датчик может учитывать гостевой переключатель и другие исключения для вашего дома. Сценарий принимает как `on`/`off`, так и `home`/`not_home` и не вычисляет присутствие заново.

<a id="configuration"></a>
## Настройка

- **Consolidated occupancy state:** одна сущность, уже объединяющая сведения о присутствии во всём доме.
- **When occupied:** одно или несколько стандартных действий Home Assistant при присутствии.
- **When empty:** одно или несколько стандартных действий Home Assistant при отсутствии.
- **Occupied delay:** сколько времени сущность должна непрерывно находиться в состоянии `on` или `home`.
- **Empty delay:** сколько времени сущность должна непрерывно находиться в состоянии `off` или `not_home`.
- **Availability warning delay:** сколько должно сохраняться состояние `unknown` или `unavailable`, прежде чем Home Assistant создаст диагностическое уведомление. По умолчанию — 5 минут.

<a id="example"></a>
## Пример

Для действия при присутствии добавьте **Select: Select**, выберите доступную в Home Assistant сущность режима Velair и вариант `Home`. Аналогично настройте действие при отсутствии с вариантом `Away`. Выбирайте сущность в интерфейсе, а не предполагайте конкретный идентификатор.

Созданные действия эквивалентны следующему:

```yaml
action: select.select_option
target:
  entity_id: select.velair_mode
data:
  option: Home
```

Чтобы вместо этого напрямую активировать профиль:

```yaml
action: velair.activate_profile
data:
  profile_id: home
```

Для вариантов «Дома», «Отсутствие» и «Отпуск» обычно понятнее использовать режимы, поскольку текущее состояние видно в селекторе режима Velair в Home Assistant.

<a id="how-it-works"></a>
## Как это работает

Триггеры присутствия (`on`/`home`) и отсутствия (`off`/`not_home`) используют стандартную длительность `for` Home Assistant: состояние должно сохраняться непрерывно в течение всей задержки. Отдельные шаблонные триггеры доступности выявляют длительное состояние `unknown`/`unavailable` и восстановление до любого поддерживаемого состояния. По истечении задержки предупреждения Home Assistant создаёт одно постоянное уведомление для этой автоматизации, обновляет его без дублирования и закрывает после восстановления. Действия присутствия и отсутствия не выполняются, пока у сущности нет допустимого состояния.

При запуске проверки присутствия, отсутствия и доступности выполняются в отдельных параллельных ветвях. Каждая проверяет начальное состояние, ожидает противоположного состояния с возможностью прерывания в пределах заданного времени и продолжает только по истечении этого времени, повторно проверяя состояние перед действием. Внешний параллельный режим с ограничением числа запусков не позволяет ожиданию доступности при старте заблокировать последующий переход в допустимое состояние присутствия. Периодического опроса нет.

<a id="safety-and-precedence"></a>
## Безопасность и приоритеты

Сценарий выполняет только настроенные вами действия. Существующие приоритеты режимов, профилей, форсированных режимов и пауз Velair продолжают действовать. Сущность присутствия со значением `unknown` или `unavailable` не активирует ни присутствие, ни отсутствие; предупреждение указывает сущность и объясняет, что действия приостановлены до получения поддерживаемого состояния присутствия или отсутствия.

<a id="limitations"></a>
## Ограничения

- Сценарий намеренно принимает одну сущность с уже рассчитанным присутствием и сам не объединяет правила для людей или гостей.
- Таймеры `for` Home Assistant не сохраняются после перезапуска, поэтому при старте настроенная задержка начинается заново.
- Идентификатор уведомления использует идентификатор сущности автоматизации. После переименования автоматизации прежнее уведомление может остаться; его нужно закрыть вручную.
- Параллельное выполнение ограничено 20 запусками. Если необычно большой поток событий займёт все места, появится предупреждение.
- Действия, для которых выбрано **Take control**, больше не получают обновления сценария автоматически.

<a id="troubleshooting"></a>
## Устранение проблем

- Если ни одна ветвь не запускается, убедитесь, что выбранная сущность сообщает `on`/`home` или `off`/`not_home`.
- Если появилось предупреждение, проверьте указанную сущность присутствия и исходную группу, шаблон, людей или гостевой переключатель.
- Если отсутствие активируется слишком быстро, увеличьте задержку отсутствия.
- Если ожидаемый режим не выбирается, выполните выбранное действие вручную в Home Assistant и проверьте название варианта.
- Если действие профиля не выполняется, используйте стабильный идентификатор профиля вместо редактируемого отображаемого имени.

<a id="updating-and-customizing"></a>
## Обновление и изменение сценария

Повторно импортируйте обновляемый URL ветки `main`, чтобы установить совместимое обновление. Обновления версии 1 сохраняют существующие имена входных параметров, а у каждого нового параметра есть значение по умолчанию, поэтому переносить автоматизацию не нужно. Будущая несовместимая версия получит новое имя файла и основной номер версии вместо замены этого URL. Velair никогда не изменяет автоматизации Home Assistant или `.storage` для переноса сценария. Используйте **Take control** только тогда, когда нужную логику нельзя выразить через доступные параметры; после этого независимая автоматизация перестанет получать обновления сценария.
