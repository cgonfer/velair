Velair is available in the default HACS store. Manual installation remains
available for users who do not use HACS or who need to test a specific build.

## HACS

1. Open HACS.
2. Search for **Velair** in the available integrations.
3. Open Velair and select **Download**.
4. Restart Home Assistant.
5. Go to **Settings > Devices & services**.
6. Add the Velair integration.
7. Select the `climate.*` entities Velair may manage.

Velair uses the temperature unit selected in Home Assistant. A new installation
creates schedules, templates, Comfort thresholds, Room Assist settings, and
Adaptive Preconditioning defaults for that unit. The unit is shown read-only in
Velair Settings and must be changed through Home Assistant, not Velair.

Existing installations upgrading from a published Celsius-only Velair version
may need a reset when Home Assistant uses Fahrenheit. Review
[Temperature Units and Migration](temperature-units.md) before proceeding so you
can export a reference copy first if needed.

## Manual Installation

Manual installation is normally only needed when you do not use HACS or when you want to test a GitHub Actions or GitHub Release build.

Release assets include `velair-custom-component-<version>.zip`. Extract it so this folder exists:

```text
<home_assistant_config>/custom_components/velair
```

For a repository checkout, copy:

```text
custom_components/velair
```

to:

```text
<home_assistant_config>/custom_components/velair
```

Restart Home Assistant and add Velair from **Settings > Devices & services**.

## GitHub Actions Artifacts

Every successful CI run uploads temporary artifacts:

- `velair-custom-component`: the complete `custom_components/velair` folder with the frontend bundle generated by that run.
- `velair-lovelace-resource`: the compiled `velair-card.js` files for advanced manual Lovelace resource testing.

Tagged release runs also attach zip files to the GitHub Release. Prefer HACS for normal use; use these artifacts when you want to test a specific workflow run or install manually.

## Optional Lovelace Card

The sidebar panel is registered automatically. The Lovelace card is optional.

Add the integration-served resource:

```yaml
url: /velair_frontend/velair-card.js
type: module
```

Then add one or more Velair cards. Each card uses the same backend data and visual components as the sidebar panel.

```yaml
type: custom:velair-card
view: overview-status
```

Supported `view` values:

- `climate`: status and controls for one managed climate, with an optional household One-off return action alongside Boost and Pause. Existing cards keep that action hidden; new card-picker configurations enable it.
- `overview-status`: scheduler state and pause/stop/resume controls.
- `overview-boosts`: active boosts.
- `overview-events`: next events.
- `overview-timeline`: today's timeline.
- `overview-zones`: zone overview.
- `active-setup`: current Mode and Profiles, with optional controls.
- `schedules`: full schedule editor.
- `sensors`: Room Assist configuration and live status.
- `comfort`: environmental comfort configuration and status.
- `preconditioning`: adaptive preconditioning configuration and local learning status.
- `planned-return`: compact one-off return controls, configured occupancy counts and a confirmed-departure timeline. Without saved occupancy sources, Plan return applies Away immediately; the automatic weekly routine still requires sources.
- `diagnostics`: runtime health, bounded history, filters, and issue-report export.

### Card discovery and resource troubleshooting

Use only the integration-served `/velair_frontend/velair-card.js` module resource.
Remove duplicate Velair resources, including an older `/local/velair-card.js`,
then reload the browser. Browser custom elements cannot be replaced after they
have registered, so an older resource loaded first can leave that browser using
an obsolete card implementation.

The dashboard card picker discovers Velair through frontend metadata. Adding
`type: custom:velair-card` manually in YAML uses the registered custom element;
these are separate checks. If the card works through YAML but does not appear in
the picker, record that distinction when reporting the problem.

If discovery differs between desktop and mobile, check the affected browser's
developer console for JavaScript errors and its Network tab for the resource
request. Include the Home Assistant and Velair versions, affected browser, exact
resource URL and any relevant error text in the report. Remove private details
before sharing logs. Successful loading in another browser does not establish
the cause of a failure in the affected browser.

## Updating

After updating Velair:

1. Restart Home Assistant.
2. Hard refresh the browser or reload the Home Assistant companion app.
3. Confirm the Settings maintenance section shows the expected integration version.
